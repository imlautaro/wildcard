Your installation works with just the API and the web app. Everything on this page is optional.

::steps{level="3"}

### Admin panel

Create a Workers Builds project for `wildcard-admin` with the commands in [Workers Builds](/en/cloudflare/workers-builds#projects) (the GitHub Actions workflow does not release it). To grant admin access, sign in on the admin origin, copy your user ID from the "Not a super admin" screen into `WILDCARD_SUPER_ADMIN_USER_IDS` (GitHub variable or API build variable) and release the API again.

### Custom domains

Set `WILDCARD_API_URL` and `WILDCARD_WEB_URL` to HTTPS origins without a path, then attach the domains to the `wildcard-api` and `wildcard-web` Workers in the Cloudflare dashboard (that step is not automated). When both are set, the `workers.dev` subdomain is not needed. See [Environment variables](/en/getting-started/environment-variables).

### iPhone app

Signing team, bundle IDs, `WILDCARD_API_URL`, `WILDCARD_APP_GROUP`, `WILDCARD_LINK_HOST`, capabilities and APNs key (see [iOS app](/en/apps/ios#configuring-for-your-own-account)).

### AI Gateway

`npm run infra:ai-gateway -- --create`, then set `AI_GATEWAY_ID` and push once verified.

### Marketing site and docs

Create one Workers Builds project each with the commands in [Workers Builds](/en/cloudflare/workers-builds#projects). Set the site URLs in `apps/site/app/utils/site.ts` and the Docs URL in `apps/docs/nuxt.config.ts`.
::

::warning
`WILDCARD_SUPER_ADMIN_USER_IDS` is applied on every API release. Removing or emptying it revokes all admin access on the next release.
::

## Staging

No staging environment exists. A staging setup needs its own Worker names, D1 database, R2 bucket, Workflow names, secrets, origins and iOS configuration. Never point Previews or staging at the production database unintentionally (web Previews currently use the production API by design).
