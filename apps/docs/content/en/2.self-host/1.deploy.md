Wildcard runs entirely on Cloudflare: Workers, D1, R2 and Workflows. Your installation is the API and the web app on your own account, with your own database and your own keys. You don't edit anything in the repository: the account, resources and URLs are resolved when it is released, and the first release creates the D1 database and the private R2 bucket.

## What you need

- A **Cloudflare account** with Workers, D1, R2 and Workflows available on its plan, and a `workers.dev` subdomain (opening **Workers & Pages** once in the dashboard creates it).
- A **GitHub account**.
- A **Meta Model API key** with access to Muse Spark 1.3 and Muse Voice Transcribe.
- Optional: an **ElevenLabs** key for contact voices, an **Apple Developer** account for the iPhone app and its notifications (APNs, App Groups, Associated Domains), and **VAPID** keys for web push (`node scripts/generate-vapid-keys.mjs`).

## Deploy to Cloudflare

The quickest way, and the one we recommend:

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button){width="220" :zoom="false"}](https://deploy.workers.cloudflare.com/?url=https://github.com/imlautaro/wildcard)

::steps{level="3"}

### Click the button

It copies the repository into your GitHub account (a new repository with one "source repo import" commit, not a fork) and creates one Workers Builds project connected to the Worker `wildcard-api`. Its deploy command, `npm run deploy`, releases the API and then builds and releases the web app, so both Workers come from that single project.

### Fill in the form

- Keep the Worker name **`wildcard-api`**. The web app's service binding targets it; a renamed project fails with a message that says so.
- Enter `META_API_KEY`. The form asks for every key in the root `.env.example`; it becomes a secret of the `wildcard-api` Worker, and releases keep it.
- Keep the prefilled commands: build `npm run build`, deploy `npm run deploy`.

### Wait for the first build

It takes about two minutes because it applies every migration. Your app is then at `https://wildcard-web.<subdomain>.workers.dev`, where `<subdomain>` is your account's `workers.dev` subdomain. Replies can be delayed for the first minutes, see [Troubleshooting](/en/operations/troubleshooting).

### Add the optional keys

For contact voices, add `ELEVENLABS_API_KEY` as a secret of the `wildcard-api` Worker (**Settings → Variables and secrets**). From now on, every push to the new repository's `main` releases both Workers.
::

## Other ways to deploy

Prefer a fork with GitHub Actions, or one Workers Builds project per Worker? Choose **one** method per installation: running two for the same Workers releases them twice.

::tabs
  :::tabs-item{label="GitHub Actions"}
  `.github/workflows/deploy.yml` is opt-in. On every push to `main` (or a manual run) it type-checks, releases the API, then builds and releases the web app. It does not release the admin panel, site or docs, and it builds no branch Previews.

  Fork the repository, then in the fork open **Settings → Secrets and variables → Actions** and add:

  | Kind | Name | Required |
  | --- | --- | --- |
  | Variable | `WILDCARD_DEPLOY` = `true` | Yes (turns the workflow on) |
  | Secret | `CLOUDFLARE_API_TOKEN` | Yes |
  | Secret | `META_API_KEY` | Yes |
  | Secret | `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*` | Optional (each group all or none) |
  | Variable | `CLOUDFLARE_ACCOUNT_ID` | When the token can see several accounts |
  | Variable | `WILDCARD_API_URL`, `WILDCARD_WEB_URL`, `WILDCARD_SUPER_ADMIN_USER_IDS` | Optional |

  Create the API token from the **Edit Cloudflare Workers** template, add **Account → D1 → Edit**, and limit it to your account (no zones are needed). Never commit its value.

  Enable Actions in the fork, then push to `main` or run the **Deploy** workflow manually. The first run creates D1, R2, both Workers, the Workflows and the Cron trigger.
  :::

  :::tabs-item{label="Workers Builds"}
  Connect one Workers Builds project per Worker to your fork, branch `main`, root `/`:

  - **API** (`wildcard-api`): build `npm ci && npm run typecheck`, deploy `npm run release:ci`, previews disabled. Credential: Workers Scripts edit, D1 edit, Workflows edit, R2 edit and account read. Add the encrypted build secret `META_API_KEY` (and optional `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*`). Add `CLOUDFLARE_ACCOUNT_ID`, `WILDCARD_API_URL`, `WILDCARD_WEB_URL` or `WILDCARD_SUPER_ADMIN_USER_IDS` as build variables only when you need them.
  - **Web** (`wildcard-web`), after the API exists: build `npm ci && npm run typecheck:web && npm run build:web`, deploy `npm run release:web`. Credential: Workers Scripts edit and account read. For branch Previews, enable non-production builds with the preview command `npm run preview:web`.

  Copy the include paths from `docs/workers-build-paths.json` into each project's **Settings → Builds** and remove the default `*` (see [watch paths](/en/cloudflare/workers-builds#watch-paths)). Push a commit: the API release creates D1 and R2 if needed, migrates D1, generates `BETTER_AUTH_SECRET`, uploads secrets and publishes the API with its Workflows and Cron.
  :::
::

## Check that it works

Sign up in your web app and talk to a contact. To check it from a terminal (Node.js 24+, in a clone of the repository):

```bash [Terminal]
npm run smoke -- https://wildcard-web.<subdomain>.workers.dev
```

The smoke test signs up a throwaway account, creates a contact, sends a message and waits for the model's reply, which proves the web proxy, auth, D1, Workflows and `META_API_KEY` together. The account it creates stays; delete it from the app's Account settings. See [Releases](/en/operations/releases#verifying-a-release) for the checks that need no account.
