The versioned Wrangler files are account-neutral: they contain no `account_id`, no real D1 ID, no installation URLs and no admin IDs. A fork deploys with **zero edits to versioned files**. At release time `scripts/release-worker.mjs` resolves the installation for the target account into the ignored `apps/api/wrangler.release.json`, and the first release creates the D1 database and the private R2 bucket. The canonical, more detailed version is `docs/infrastructure.md`.

## What the release resolves

| Value | Source |
| --- | --- |
| Cloudflare account | `CLOUDFLARE_ACCOUNT_ID`, otherwise the only account the credential can see |
| D1 database | Looked up by name (`wildcard-db`, or `WILDCARD_DB_NAME`); created if missing |
| R2 bucket | `wildcard-contact-photos` (or `WILDCARD_PHOTOS_BUCKET`), private; created if missing |
| `BETTER_AUTH_URL` | `WILDCARD_API_URL`, otherwise `https://wildcard-api.<subdomain>.workers.dev` |
| `MCP_WEB_ORIGIN` | `WILDCARD_WEB_URL`, otherwise `https://wildcard-web.<subdomain>.workers.dev` |
| `SUPER_ADMIN_USER_IDS` | `WILDCARD_SUPER_ADMIN_USER_IDS` (empty: nobody can use the admin panel) |

`<subdomain>` is the account's `workers.dev` subdomain. Empty CI values count as unset. `BETTER_AUTH_SECRET` is generated only on the first release and kept afterwards.

## Check the account first

Optional, because the first release creates the missing resources itself. Both commands need Node.js 24+ and `npx wrangler login`, use your local Wrangler login and never deploy, migrate or edit versioned files:

```bash [Terminal]
npm run release:check                 # dry run: resolved account, origins, D1, R2, missing secrets
npm run infra:provision               # shows the resources; -- --create creates D1 and R2 now
```

`npm run infra:photos` is an alias of `infra:provision`.
