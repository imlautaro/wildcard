This is the order in which to create resources so that every binding exists before the code that uses it is released. The canonical, more detailed version is `docs/infrastructure.md`.

## Prerequisites

- A Cloudflare account with Workers, D1, R2 and Workflows available on its plan.
- A GitHub repository with this code, connected to Cloudflare through the Workers Builds GitHub integration.
- Node.js 24+ and a Wrangler login with account read, D1 edit and R2 edit (for provisioning only).
- A Meta Model API key with Muse Spark 1.3 and Muse Voice Transcribe access.
- Optional: ElevenLabs key, Apple Developer account (APNs, App Groups, Associated Domains), VAPID keys.

## Steps

::steps{level="3"}

### Replace account-specific values

In `apps/api/wrangler.jsonc`: `account_id`, Worker `name`, `vars.BETTER_AUTH_URL`, `vars.MCP_WEB_ORIGIN`, `vars.SUPER_ADMIN_USER_IDS` (start empty), Workflow `name`s, R2 `bucket_name`. Set the D1 `database_name` and its `database_id` to `00000000-0000-0000-0000-000000000000`. Keep every `binding` and `class_name`. Replace `account_id` in the web, admin, site and docs Wrangler files, and the service names if your API Worker has another name.

### Create the D1 database

```bash [Terminal]
npm run infra:provision
```

It lists databases, reuses a matching name or creates one, verifies the ID and writes it into the binding. It refuses to replace a different non-placeholder ID and never migrates or deploys.

### Create the R2 bucket

```bash [Terminal]
npm run infra:photos -- --create
npm run infra:photos
```

Keep `r2.dev` and public custom domains disabled.

### Commit and push the configuration

Review the account and IDs, then commit and push.

### Connect the API Workers Builds project

Repository and branch `main`, root `/`, build `npm ci && npm run typecheck`, deploy `npm run release:ci`, previews disabled. Credential: Workers Scripts edit, D1 edit, Workflows edit, R2 bucket access and account read. Add the encrypted build secret `META_API_KEY` (and optional `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*`). Push a commit: the release migrates D1, generates `BETTER_AUTH_SECRET`, uploads secrets and publishes the API with its Workflows and Cron.

### Connect the web project

Root `/`, build `npm ci && npm run typecheck:web && npm run build:web`, deploy `npm run release:web`. Credential: Workers Scripts edit and account read. For branch Previews, enable non-production builds with the preview command `npm run preview:web`.

### Optional: admin, site and docs

Create one project each with the commands in [Workers Builds](/en/cloudflare/workers-builds#projects). Then sign in on the admin origin, add your user ID to `SUPER_ADMIN_USER_IDS` and push. Set the site URLs in `apps/site/app/utils/site.ts` and the docs URL in `apps/docs/nuxt.config.ts`.

### Optional: AI Gateway

`npm run infra:ai-gateway -- --create`, then set `AI_GATEWAY_ID` and push once verified.

### Configure the watch paths

Copy the include paths from `docs/workers-build-paths.json` into each project's **Settings → Builds** and remove the default `*`.

### Configure the iOS app

Signing team, bundle IDs, `WILDCARD_API_URL`, `WILDCARD_APP_GROUP`, `WILDCARD_LINK_HOST`, capabilities and APNs key (see [iOS app](/en/apps/ios#configuring-for-your-own-account)).
::

## Staging

No staging environment exists. A staging setup needs its own Worker names, D1 database, R2 bucket, Workflow names, secrets, origins and iOS configuration. Never point Previews or staging at the production database unintentionally (web Previews currently use the production API by design).
