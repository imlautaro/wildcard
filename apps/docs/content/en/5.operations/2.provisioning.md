The versioned Wrangler files are account-neutral: they contain no `account_id`, no real D1 ID, no installation URLs and no admin IDs. A fork deploys with **zero edits to versioned files**. At release time `scripts/release-worker.mjs` resolves the installation for the target account into the ignored `apps/api/wrangler.release.json`, and the first release creates the D1 database and the private R2 bucket. The canonical, more detailed version is `docs/infrastructure.md`.

## What the release resolves

| Value | Source |
| --- | --- |
| Cloudflare account | `CLOUDFLARE_ACCOUNT_ID`, otherwise the only account the credential can see |
| D1 database | Looked up by name (`wildcard-db`, or `WILDCARD_DB_NAME`); created if missing |
| R2 bucket | `wildcard-contact-photos` (or `WILDCARD_PHOTOS_BUCKET`), private; created if missing |
| `BETTER_AUTH_URL` | `WILDCARD_API_URL`, otherwise `https://wildcard-api.<subdomain>.workers.dev` |
| `MCP_WEB_ORIGIN` | `WILDCARD_WEB_URL`, otherwise `https://wildcard-web.<subdomain>.workers.dev` |
| `SUPER_ADMIN_USER_IDS` | `WILDCARD_SUPER_ADMIN_USER_IDS` (empty: nobody can use the admin panel) |

`<subdomain>` is the account's `workers.dev` subdomain. Empty CI values count as unset. `BETTER_AUTH_SECRET` is generated only on the first release and kept afterwards.

## Prerequisites

- A Cloudflare account with Workers, D1, R2 and Workflows available on its plan, and a `workers.dev` subdomain (opening **Workers & Pages** once in the dashboard creates it), unless you set both `WILDCARD_API_URL` and `WILDCARD_WEB_URL`.
- A GitHub fork (or copy) of this repository.
- A Meta Model API key with Muse Spark 1.3 and Muse Voice Transcribe access.
- Optional: ElevenLabs key, Apple Developer account (APNs, App Groups, Associated Domains), VAPID keys (`node scripts/generate-vapid-keys.mjs`).
- Optional, to check the account before the first push: Node.js 24+ and `npx wrangler login`.

## Optional: check the account first

Both commands use your local Wrangler login and never deploy, migrate or edit versioned files:

```bash [Terminal]
npm run release:check                 # dry run: resolved account, origins, D1, R2, missing secrets
npm run infra:provision               # shows the resources; -- --create creates D1 and R2 now
```

This is optional, because the first release creates the missing resources itself. `npm run infra:photos` is an alias of `infra:provision`.

## Deploy the API and the web app

Choose **one** CI system per Worker. Running both for the same Worker releases it twice.

::tabs
  :::tabs-item{label="GitHub Actions"}
  `.github/workflows/deploy.yml` is opt-in. On every push to `main` (or a manual run) it type-checks, releases the API, then builds and releases the web app. It does not release the admin panel, site or docs, and it builds no branch Previews.

  In the fork, open **Settings → Secrets and variables → Actions** and add:

  | Kind | Name | Required |
  | --- | --- | --- |
  | Variable | `WILDCARD_DEPLOY` = `true` | Yes (turns the workflow on) |
  | Secret | `CLOUDFLARE_API_TOKEN` | Yes |
  | Secret | `META_API_KEY` | Yes |
  | Secret | `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*` | Optional (each group all or none) |
  | Variable | `CLOUDFLARE_ACCOUNT_ID` | When the token can see several accounts |
  | Variable | `WILDCARD_API_URL`, `WILDCARD_WEB_URL`, `WILDCARD_SUPER_ADMIN_USER_IDS` | Optional |

  Create the API token scoped to your account only, with **Workers Scripts edit, D1 edit, Workers R2 Storage edit and Account settings read** (exact permission names to be confirmed). Never commit its value.

  Push to `main` or run the **Deploy** workflow manually. The first run creates D1, R2, both Workers, the Workflows and the Cron trigger.
  :::

  :::tabs-item{label="Workers Builds"}
  Connect one Workers Builds project per Worker to the fork, branch `main`, root `/`:

  - **API** (`wildcard-api`): build `npm ci && npm run typecheck`, deploy `npm run release:ci`, previews disabled. Credential: Workers Scripts edit, D1 edit, Workflows edit, R2 edit and account read. Add the encrypted build secret `META_API_KEY` (and optional `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*`). Add `CLOUDFLARE_ACCOUNT_ID`, `WILDCARD_API_URL`, `WILDCARD_WEB_URL` or `WILDCARD_SUPER_ADMIN_USER_IDS` as build variables only when you need them.
  - **Web** (`wildcard-web`), after the API exists: build `npm ci && npm run typecheck:web && npm run build:web`, deploy `npm run release:web`. Credential: Workers Scripts edit and account read. For branch Previews, enable non-production builds with the preview command `npm run preview:web`.

  Copy the include paths from `docs/workers-build-paths.json` into each project's **Settings → Builds** and remove the default `*` (see [watch paths](/en/cloudflare/workers-builds#watch-paths)). Push a commit: the API release creates D1 and R2 if needed, migrates D1, generates `BETTER_AUTH_SECRET`, uploads secrets and publishes the API with its Workflows and Cron.
  :::
::

## Verify

```bash [Terminal]
npm run smoke -- https://wildcard-web.<subdomain>.workers.dev
```

The smoke test signs up a throwaway account, creates a contact, sends a message and waits for the model's reply, which proves the web proxy, auth, D1, Workflows and `META_API_KEY` together. The account it creates stays; delete it from the app's Account settings. See [Releases](/en/operations/releases#verifying-a-release) for the checks that need no account.

## Optional steps

::steps{level="3"}

### Admin panel, site and docs

Create one Workers Builds project each with the commands in [Workers Builds](/en/cloudflare/workers-builds#projects) (the GitHub Actions workflow does not release them). To grant admin access, sign in on the admin origin, copy your user ID from the "Not a super admin" screen into `WILDCARD_SUPER_ADMIN_USER_IDS` (GitHub variable or API build variable) and release the API again. Set the site URLs in `apps/site/app/utils/site.ts` and the docs URL in `apps/docs/nuxt.config.ts`.

### AI Gateway

`npm run infra:ai-gateway -- --create`, then set `AI_GATEWAY_ID` and push once verified.

### iOS app

Signing team, bundle IDs, `WILDCARD_API_URL`, `WILDCARD_APP_GROUP`, `WILDCARD_LINK_HOST`, capabilities and APNs key (see [iOS app](/en/apps/ios#configuring-for-your-own-account)).
::

::warning
`WILDCARD_SUPER_ADMIN_USER_IDS` is applied on every API release. Removing or emptying it revokes all admin access on the next release.
::

## Staging

No staging environment exists. A staging setup needs its own Worker names, D1 database, R2 bucket, Workflow names, secrets, origins and iOS configuration. Never point Previews or staging at the production database unintentionally (web Previews currently use the production API by design).
