## Local development

::accordion
  :::accordion-item{label="Sending a message returns 503" icon="i-lucide-circle-alert"}
  `META_API_KEY` is missing from `apps/api/.dev.vars`. Auth and contacts work without it; replies need it. Restart `npm run dev` after editing `.dev.vars`.
  :::

  :::accordion-item{label="Port 8787 or 3000 is already in use" icon="i-lucide-circle-alert"}
  `npm run dev` and `npm run dev:all` stop instead of moving to another port, because the web proxy, `BETTER_AUTH_URL` and the local cron would otherwise talk to whatever holds the port. Stop the other process (often another Wildcard checkout), or pick other ports with `API_PORT` / `WEB_PORT` in the environment or the root `.env`, for example `API_PORT=8797 npm run dev:all`.
  :::

  :::accordion-item{label="Local data disappeared after pulling" icon="i-lucide-circle-alert"}
  The versioned local D1 ID changed to a placeholder, so Wrangler opened a new, empty local database. Run `npm run setup` once to apply the migrations to it.
  :::

  :::accordion-item{label="wrangler dev asks for a Cloudflare login" icon="i-lucide-circle-alert"}
  Start the API with `npm run dev` (or `npm run dev:all`), not a bare `wrangler dev`: the script leaves out the always-remote Workers AI binding so no login is needed.
  :::

  :::accordion-item{label="Auth fails with a secret error" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` is missing or shorter than 32 characters. Run `npm run setup` (it never overwrites existing values; delete a broken file first).
  :::

  :::accordion-item{label="SQL errors about missing tables or columns" icon="i-lucide-circle-alert"}
  Your local D1 is behind. Run `npm run db:migrate:local`.
  :::

  :::accordion-item{label="The admin panel shows 404 or 'Not a super admin'" icon="i-lucide-circle-alert"}
  Set `ADMIN_LOCAL_ROUTES=true` and your local user ID in `SUPER_ADMIN_USER_IDS` in `.dev.vars`, then restart the API.
  :::

  :::accordion-item{label="Types are out of date after editing wrangler.jsonc" icon="i-lucide-circle-alert"}
  Run `npm run types --workspace @wildcard/api` (or `npm run typecheck`, which includes it).
  :::

  :::accordion-item{label="vue-tsc fails to load TypeScript" icon="i-lucide-circle-alert"}
  The Nuxt apps type-check with the aliased `typescript6` package through their `scripts/typecheck.mjs`. Run the npm script instead of calling `vue-tsc` directly.
  :::

  :::accordion-item{label="MCP OAuth does not work locally" icon="i-lucide-circle-alert"}
  OAuth requires public HTTPS origins for the API and the web app. Use public or Bearer connections locally.
  :::

  :::accordion-item{label="The web app crashes at startup after adding a composable" icon="i-lucide-circle-alert"}
  Check for an import cycle through `useSession`. It must not import other composables.
  :::
::

## Production

::accordion
  :::accordion-item{label="A release refuses to run" icon="i-lucide-circle-alert"}
  Read the guard message: it must run in Workers Builds or the GitHub Actions deploy workflow, on the production branch, with a clean checkout and `HEAD` equal to the triggering commit (`WORKERS_CI_COMMIT_SHA` or `GITHUB_SHA`). The first build after connecting a repository may lack metadata; push another commit. Do not bypass the guard with a manual deploy. `npm run release:check` lists the problems without releasing.
  :::

  :::accordion-item{label="The GitHub Actions Deploy workflow is skipped" icon="i-lucide-circle-alert"}
  The job runs only when the repository variable `WILDCARD_DEPLOY` is exactly `true`. Set it under **Settings → Secrets and variables → Actions → Variables**.
  :::

  :::accordion-item{label="The credential can access several accounts" icon="i-lucide-circle-alert"}
  The release cannot choose an account on its own. Set `CLOUDFLARE_ACCOUNT_ID` as a GitHub Actions variable or a Workers Builds build variable (locally, export it before `npm run release:check`), or scope the token to one account.
  :::

  :::accordion-item{label="This account has no workers.dev subdomain" icon="i-lucide-circle-alert"}
  The default origins are `https://<worker>.<subdomain>.workers.dev`. Open **Workers & Pages** once in the Cloudflare dashboard to create the subdomain, or set both `WILDCARD_API_URL` and `WILDCARD_WEB_URL` to your own `https://` origins, then release again.
  :::

  :::accordion-item{label="The API release stops about META_API_KEY" icon="i-lucide-circle-alert"}
  The CI secret is empty, or absent both in CI and at runtime. Set the encrypted Workers Builds build variable (or the GitHub Actions secret) and push again.
  :::

  :::accordion-item{label="The API release asks to configure APNs or VAPID secrets together" icon="i-lucide-circle-alert"}
  Only part of the `APNS_*` (four) or `VAPID_*` (three) group is set. Set all of them or none; empty values count as unset.
  :::

  :::accordion-item{label="The admin build fails after an API change" icon="i-lucide-circle-alert"}
  The admin binding may reference an `AdminAPI` change that the API has not released yet. Retry the admin build after `wildcard-api` succeeds.
  :::

  :::accordion-item{label="Replies fail with HTTP 502 through the AI Gateway" icon="i-lucide-circle-alert"}
  This happened on October 27, 2026. Clear `AI_GATEWAY_ID` (direct calls) and push; investigate the gateway separately.
  :::

  :::accordion-item{label="Everyone was signed out" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` changed (rotation, or the Worker was deleted and recreated). Sessions and encrypted MCP credentials from the old secret are no longer valid.
  :::

  :::accordion-item{label="No push notifications arrive" icon="i-lucide-circle-alert"}
  Check that all four `APNS_*` (or all three `VAPID_*`) build secrets are set and released, that `APNS_TOPIC` matches the bundle ID and that the app's `APNS_ENVIRONMENT` matches the signing. Look for `push_accepted`, `push_provider_signing_failed` or `push_delivery_deferred` events in Workers Logs.
  :::

  :::accordion-item{label="A turn is stuck in Typing" icon="i-lucide-circle-alert"}
  The minute Cron's `recoverChats` reconciles turns with their Workflow status. Check the Workflow instance in the dashboard (`chat-<turnID>-a1`) and Workers Logs for model errors.
  :::
::

## Where to look

- **Workers Logs and traces** in the Cloudflare dashboard for each Worker (sanitized events only).
- **Workflows** dashboard for instance status and step history.
- **Workers Builds** logs for build and release output.
- The feature guide in `docs/` for known limitations and pending verification.
