The web app (`@wildcard/web`, Worker `wildcard-web`) is a Nuxt 4 **single-page app** (`ssr: false`) built with the Nitro `cloudflare_module` preset. Its only server code is the API proxy and the `apple-app-site-association` file. Feature guide: [`docs/web.md`](/en/reference/web).

## Configuration highlights

```ts [apps/web/nuxt.config.ts (excerpt)]
export default defineNuxtConfig({
  extends: ['../../packages/ui'],
  modules: ['@nuxtjs/i18n'],
  ssr: false,
  runtimeConfig: { apiOrigin: 'http://localhost:8787' }, // development only
  nitro: {
    preset: 'cloudflare_module',
    cloudflare: { deployConfig: true, nodeCompat: true, wrangler: { preview_urls: true } },
  },
  i18n: { strategy: 'no_prefix', defaultLocale: 'en', detectBrowserLanguage: false /* … */ },
});
```

`nitro.cloudflare.wrangler` overrides `apps/web/wrangler.jsonc`; Nitro merges both into `.output/server/wrangler.json`, which is what the release deploys.

## Routes

| Area | Pages |
| --- | --- |
| Auth and onboarding | `/sign-in`, `/onboarding`, `/join`, `/invitations` |
| Chats | `/chats`, `/chats/[id]` |
| Contacts | `/contacts`, `/contacts/new`, `/contacts/[id]/{edit, personality, sharing, links, learning, tasks, connections}`, mini apps and documents |
| Groups | `/groups/new`, `/groups/[id]`, `/groups/[id]/{members, learning, tasks, connections}`, mini apps and documents |
| For you | `/updates` |
| Account | `/account`, `/account/connections`, `/mcp/oauth-complete` |
| Native fallback | `/native`, `/native/contact` (authorized contact links opened outside iOS) |

`app/middleware/auth.global.ts` restores the session, sends signed-out users to `/sign-in` and unfinished accounts to `/onboarding`.

## The API proxy

`server/api/v1/[...path].ts` is the only path to the API. In production it calls the `API` service binding; in development it calls `runtimeConfig.apiOrigin`. It allowlists methods, request headers and response headers, enforces same-origin for mutations, forwards `CF-Connecting-IP` and converts the session cookie into a bearer header. See [Workers → Service bindings](/en/cloudflare/workers#service-bindings).

| Cookie | `__Host-wildcard_session` (`wildcard_session` in development) |
| --- | --- |
| Attributes | `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, 7 days |
| Set | On sign-in/sign-up from the API's `set-auth-token` header; refreshed by a successful `GET /api/v1/me` |
| Cleared | On sign-out or a `401` |

The browser never sees the token, so XSS cannot exfiltrate it and the API needs no CORS.

## Data layer and caching

- `app/utils/api.ts` performs same-origin `fetch('/api/v1/…', { credentials: 'same-origin', cache: 'no-store' })`. A `401` expires the session; `0`, `502`, `503` and `504` are treated as transient failures that keep cached content visible.
- There is no Pinia. **37 composables** hold session-owned state in module-scoped refs and register a reset with `useSession`, so signing out or switching accounts clears every cache.
- Conversations keep up to 20 chats in memory; images use a 150-entry blob URL LRU. The cache rules for every feature are in [`docs/caching.md`](/en/reference/caching).

::warning
`useSession` must not import other composables: an import cycle crashed production on November 1, 2026. Register resets from the other direction.
::

The chat list shows **Draft:** for unfinished text only after leaving its private chat or group. While that conversation is open, its row keeps the normal activity, reaction, or last-message preview. Reopening restores the text in the composer and hides the draft label; drafts stay in session memory only.

## Polling

`usePolling` only runs while the tab is visible and refreshes immediately when it becomes visible again.

| What | Interval |
| --- | --- |
| Open chat or group, chat list | 1 s |
| Invitations, For you badge | 15 s |
| Onboarding circle | 3 s |
| Energy, phones, message info, documents, task boards | 5–20 s |
| For you feed | 4 s while curating, otherwise 60 s |
| Hidden tab (Web Push enabled) | List refresh every 30 s |

## Web Push

`public/sw.js` handles push only: it caches nothing and never intercepts fetches. `useWebPush` registers it, reads the VAPID key from `/api/v1/push/web-key`, stores the subscription with `PUT /api/v1/push/web-device` and shows the unread count in the tab title (`Wildcard (N)`). Notifications are suppressed for a chat that is visible in a tab.

## Localization and appearance

- English and Spanish with `@nuxtjs/i18n` (`no_prefix`), one JSON file per area in `i18n/locales/<en|es>/`. Account → Language offers System, English and Español (`localStorage` key `wildcard-language`).
- System, Light or Dark theme from the UI layer (`localStorage` key `wildcard-theme`). Dark CSS must target `:root[data-theme="dark"]`.

## Platform differences

The web app matches iOS feature for feature, except where browsers cannot: no APNs (Web Push instead), no native timers, alarms, Calendar or Reminders (a guide and contact-link fallback instead), and a web-only debug export.
