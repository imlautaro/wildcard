The admin panel (`@wildcard/admin`, Worker `wildcard-admin`) is an optional Nuxt 4 SPA in English. It shares the UI layer with the web app. Feature guide: `docs/admin.md`.

## What super admins can do

- Open or close **registration** (`registration_enabled`).
- Enable **contact voice messages** (`voice_messages_enabled`).
- Force **Contributor for every account** (`contributor_only`) during testing; saved model choices return when it is turned off.
- List accounts with their contact counts and **delete an account** with all its owned data. Deletion is durable: R2 objects and Workflow instances are removed asynchronously through the cleanup outbox (migration 0069).
- Inspect lab views such as mini apps.

Pages: `/`, `/sign-in`, `/users`, `/settings`, `/mini-apps`. Changes are recorded in `admin_event`.

## Access model

```text
Browser ──cookie──▶ wildcard-admin ──service binding (entrypoint AdminAPI)──▶ wildcard-api
```

- The binding targets the named entrypoint `AdminAPI`, a `WorkerEntrypoint` that serves the admin Hono app. It is **not reachable from the public API origin**: `GET /api/v1/admin/session` on the API origin returns `404`.
- The admin proxy forwards only sign-in, sign-out and `/api/v1/admin/*`; `/api/v1/me` returns `404` on the admin origin.
- Authorization is a roster: `SUPER_ADMIN_USER_IDS` (comma-separated user IDs, a plain variable in `apps/api/wrangler.jsonc`). Anyone else gets `403 NOT_SUPER_ADMIN`.
- Session cookie: `__Host-wildcard_admin_session` (`HttpOnly`, `Secure`, `SameSite=Strict`).

::tip
For extra protection you can put Cloudflare Access in front of `wildcard-admin`. It is not configured in this repository.
::

## Adding a super admin

1. Sign in on the admin origin. The "Not a super admin" screen shows your user ID.
2. Add it to `SUPER_ADMIN_USER_IDS` in `apps/api/wrangler.jsonc`.
3. Commit and push; the API release applies the change.

To revoke access, remove the ID and release the API. The panel itself stores no data.

## Local development

See [Local development → Admin panel locally](/en/getting-started/local-development#admin-panel-locally): `wrangler dev` cannot serve named entrypoints, so `ADMIN_LOCAL_ROUTES=true` in `.dev.vars` mounts the admin routes on the local public app.

## Release order

If the admin build runs before the API release that exports a new `AdminAPI` change, the binding may point to code that does not exist yet. Retry the admin build after `wildcard-api` succeeds.
