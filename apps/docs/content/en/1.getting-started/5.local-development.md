## Prerequisites

- **Node.js 24 or later** and npm (the repository pins `24` in `.nvmrc`).
- macOS with **Xcode 27.1 or later** for the iOS app (deployment target iOS 27.0).
- No Cloudflare account or login is needed for local emulation: Wrangler emulates D1, R2 and Workflows on your machine.
- Optional: a Meta Model API key with Muse Spark 1.3 access to generate replies locally. Calls consume real credits.

## First run

::steps{level="3"}

### Install dependencies

From the repository root, always with the root lockfile:

```bash [Terminal]
npm ci
```

### Create the local auth secret and database

```bash [Terminal]
npm run auth:setup:local
```

This writes an ignored, owner-only `apps/api/.dev.vars` with `BETTER_AUTH_URL=http://localhost:8787` and a random `BETTER_AUTH_SECRET`, then applies **every** migration in `apps/api/migrations` to Wrangler's local D1 (stored under `.wrangler/`, ignored by Git). An existing `.dev.vars` is never overwritten.

### Start the API

```bash [Terminal]
npm run dev
```

Wrangler serves the API at `http://localhost:8787`, including the Workflows and an emulated R2 bucket. Unknown paths return `404` JSON and `GET /api/v1/me` returns `401` without a session.

### Start a client

```bash [Terminal]
npm run dev:web     # http://localhost:3000
```

The web app's server proxy forwards `/api/v1/*` to `http://localhost:8787` in development (`runtimeConfig.apiOrigin`). Create an account from the sign-up screen.
::

## Enabling model features

Without `META_API_KEY`, authentication, contacts and settings work, but sending a chat message returns `503`. To generate replies, add your key to the ignored file:

```bash [apps/api/.dev.vars]
BETTER_AUTH_URL=http://localhost:8787
BETTER_AUTH_SECRET=<generated by auth:setup:local>
META_API_KEY=<your key>
META_CHAT_MODEL=muse-spark-1.3
AI_GATEWAY_ID=
```

::warning
Never commit `.dev.vars` or paste keys into issues, chats or logs. The template `apps/api/.dev.vars.example` contains only names and comments. See [Environment variables](/en/getting-started/environment-variables) for every optional value (ElevenLabs, APNs, Web Push, MCP OAuth).
::

## Admin panel locally

`wrangler dev` cannot serve a named entrypoint such as `AdminAPI` over HTTP. For local use, the API can mount the admin routes on its public app:

```bash [apps/api/.dev.vars]
ADMIN_LOCAL_ROUTES=true
SUPER_ADMIN_USER_IDS=<your local user ID>
```

```bash [Terminal]
npm run dev          # API on http://localhost:8787
npm run dev:admin    # panel on http://localhost:3001
```

Sign in on the panel; the "Not a super admin" screen shows the user ID to put in the roster. **Never** set `ADMIN_LOCAL_ROUTES` in `wrangler.jsonc`.

## Marketing site and docs

```bash [Terminal]
npm run dev:site     # http://localhost:3002
npm run dev:docs     # http://localhost:3004
```

Neither needs the API. To check the production output of a static site, build it and serve it with Wrangler's asset server:

```bash [Terminal]
npm run build:docs
cd apps/docs && npx wrangler dev --config wrangler.jsonc --port 3005
```

## iOS app

```bash [Terminal]
npm run ios    # opens apps/ios/Wildcard.xcodeproj
```

Select the `Wildcard` scheme. Debug and Release point to the public API through the `WILDCARD_API_URL` build setting. For the simulator against your local API, override the Debug value to `http://localhost:8787` (and allow local networking in App Transport Security if the OS requires it). Physical devices need a reachable HTTPS origin, because `localhost` points to the device itself. For a physical device, select your own signing team and bundle identifiers.

## Useful local commands

| Command | Purpose |
| --- | --- |
| `npm run db:migrate:local` | Apply only pending migrations to the local D1 (for example after pulling) |
| `npm run types --workspace @wildcard/api` | Regenerate `worker-configuration.d.ts` after editing `wrangler.jsonc` |
| `npm run typecheck` | API types and TypeScript check |
| `npm run typecheck:web` | Web types with `vue-tsc` |
| `npm run test:lifecycle` | Lifecycle integration tests with local D1/R2/Workflows in Miniflare |
| `node scripts/check-locales.mjs` | Validate English and Spanish messages for web and site |

## Limitations of local emulation

- **OAuth MCP connectors** need a public HTTPS `BETTER_AUTH_URL` and web origin, so they do not work on `localhost`. Public and Bearer MCP connections do.
- **APNs** requires HTTP/2, which local macOS `workerd` may not support.
- **Semantic memory** (`SEMANTIC_MEMORY_ENABLED=true`) calls the remote Workers AI binding even in local development.
- The optional **AI Gateway** is disabled locally with `AI_GATEWAY_ID=` (empty).

::tip
If the local database gets into a bad state, stop `wrangler dev`, delete the local D1 state under `apps/api/.wrangler/` and run `npm run db:migrate:local` again. Production data is never copied locally.
::
