## Prerequisites

- **Node.js 24 or later** and npm (the repository pins `24` in `.nvmrc`).
- macOS with **Xcode 27.1 or later** for the iOS app (deployment target iOS 27.0).
- No Cloudflare account or login is needed for local emulation: Wrangler emulates D1, R2, Workflows and the every-minute Cron on your machine.
- Optional: a Meta Model API key with Muse Spark 1.3 access to generate replies locally. Calls consume real credits.

## First run

::steps{level="3"}

### Install dependencies

From the repository root, always with the root lockfile:

```bash [Terminal]
npm ci
```

### Add your API keys (optional)

Copy the template to the ignored root `.env` and fill in your keys, or export them as environment variables:

```bash [Terminal]
cp .env.example .env
```

```bash [.env]
META_API_KEY=<your key>
# Optional, for contact voices:
ELEVENLABS_API_KEY=<your key>
# Optional local ports (defaults 8787 and 3000):
# API_PORT=8787
# WEB_PORT=3000
```

Production never reads this file; see [Provisioning](/en/operations/provisioning) for CI secrets.

### Create the local configuration and database

```bash [Terminal]
npm run setup
```

This checks your Node.js version, writes an ignored, owner-only `apps/api/.dev.vars` from `apps/api/.dev.vars.example` with `BETTER_AUTH_URL=http://localhost:8787` and a random `BETTER_AUTH_SECRET`, copies `META_API_KEY` and `ELEVENLABS_API_KEY` from the root `.env` or your environment without printing them, then applies **every** migration in `apps/api/migrations` to Wrangler's local D1 (stored under `.wrangler/`, ignored by Git). With an ElevenLabs key it also turns on **Contact voice messages** in the local database. It is safe to re-run: existing values are never overwritten. `npm run auth:setup:local` is an alias.

:::note
Existing checkouts must run `npm run setup` once more after pulling the account-neutral configuration: the versioned local D1 ID changed to a placeholder, so Wrangler uses a new, empty local database. Data in the previous local database is not carried over.
:::

### Start the API and the web app

```bash [Terminal]
npm run dev:all     # API on http://localhost:8787 + web app on http://localhost:3000
```

Open `http://localhost:3000` and create an account from the sign-up screen. The web app's server proxy forwards `/api/v1/*` to `http://localhost:8787` in development (`runtimeConfig.apiOrigin`). To run them in separate terminals, use `npm run dev` (API) and `npm run dev:web` (web app).

`API_PORT` and `WEB_PORT` (from the environment or the root `.env`) choose other ports, for example to run two checkouts side by side. The local `BETTER_AUTH_URL`, the local cron and, with `dev:all`, the web app's API origin follow `API_PORT`. A busy port stops the command with a message instead of silently moving to another port.

### Check it end to end (optional)

```bash [Terminal]
npm run smoke
```

With the stack running and `META_API_KEY` set, this signs up a throwaway account on the local web app (`WEB_PORT`, default 3000), creates a contact, sends a message and waits for the model's reply. It consumes real model credits.
::

## How `npm run dev` runs the API

`npm run dev` writes an ignored `apps/api/wrangler.local.json` derived from `wrangler.jsonc` and starts `wrangler dev --local` with it. Unknown paths return `404` JSON and `GET /api/v1/me` returns `401` without a session. Compared with the deployed configuration:

- The **Workers AI** binding is left out, because Wrangler always runs it remotely and would ask for a Cloudflare login. Locally it only backs the AI Gateway and semantic memory, both off by default.
- `secrets.required` is left out, so Wrangler loads **every** value in `.dev.vars`, including optional ones such as `ELEVENLABS_API_KEY`, `VAPID_*` and `ADMIN_LOCAL_ROUTES`.
- Wrangler does not fire cron triggers locally, so the script runs the Worker's scheduled handler every minute (reminders, tasks, monitors, For you, initiative and welcomes). Set `WILDCARD_LOCAL_CRON=0` to turn it off.

Deployments keep using `wrangler.jsonc` unchanged.

## Enabling model features

Without `META_API_KEY`, authentication, contacts and settings work, but sending a chat message returns `503`. If you skipped the key during setup, add it to the ignored file and restart the API:

```bash [apps/api/.dev.vars]
BETTER_AUTH_URL=http://localhost:8787
BETTER_AUTH_SECRET=<generated by npm run setup>
META_API_KEY=<your key>
META_CHAT_MODEL=muse-spark-1.3
AI_GATEWAY_ID=
```

::warning
Never commit `.dev.vars` or paste keys into issues, chats or logs. The template `apps/api/.dev.vars.example` contains only names and comments. See [Environment variables](/en/getting-started/environment-variables) for every optional value (ElevenLabs, APNs, Web Push, MCP OAuth).
::

## Admin panel locally

`wrangler dev` cannot serve a named entrypoint such as `AdminAPI` over HTTP. For local use, the API can mount the admin routes on its public app:

```bash [apps/api/.dev.vars]
ADMIN_LOCAL_ROUTES=true
SUPER_ADMIN_USER_IDS=<your local user ID>
```

```bash [Terminal]
npm run dev          # API on http://localhost:8787
npm run dev:admin    # panel on http://localhost:3001
```

Sign in on the panel; the "Not a super admin" screen shows the user ID to put in the roster. **Never** set `ADMIN_LOCAL_ROUTES` in `wrangler.jsonc`.

## Marketing site and docs

```bash [Terminal]
npm run dev:site     # http://localhost:3002
npm run dev:docs     # http://localhost:3004
```

Neither needs the API. To check the production output of a static site, build it and serve it with Wrangler's asset server:

```bash [Terminal]
npm run build:docs
cd apps/docs && npx wrangler dev --config wrangler.jsonc --port 3005
```

## iOS app

```bash [Terminal]
npm run ios    # opens apps/ios/Wildcard.xcodeproj
```

Select the `Wildcard` scheme. Debug and Release point to the public API through the `WILDCARD_API_URL` build setting. For the simulator against your local API, override the Debug value to `http://localhost:8787` (and allow local networking in App Transport Security if the OS requires it). Physical devices need a reachable HTTPS origin, because `localhost` points to the device itself. For a physical device, select your own signing team and bundle identifiers.

## Useful local commands

| Command | Purpose |
| --- | --- |
| `npm run db:migrate:local` | Apply only pending migrations to the local D1 (for example after pulling) |
| `npm run types --workspace @wildcard/api` | Regenerate `worker-configuration.d.ts` after editing `wrangler.jsonc` |
| `npm run typecheck` | API types and TypeScript check |
| `npm run typecheck:web` | Web types with `vue-tsc` |
| `npm run test:lifecycle` | Lifecycle integration tests with local D1/R2/Workflows in Miniflare |
| `node scripts/check-locales.mjs` | Validate English and Spanish messages for web and site |

## Limitations of local emulation

- **OAuth MCP connectors** need a public HTTPS `BETTER_AUTH_URL` and web origin, so they do not work on `localhost`. Public and Bearer MCP connections do.
- **APNs** requires HTTP/2, which local macOS `workerd` may not support.
- **Semantic memory** (`SEMANTIC_MEMORY_ENABLED=true`) needs the remote Workers AI binding: run `npx wrangler login`, then start the API with `WILDCARD_REMOTE_BINDINGS=1 npm run dev`.
- The optional **AI Gateway** is disabled locally with `AI_GATEWAY_ID=` (empty).

::tip
If the local database gets into a bad state, stop `wrangler dev`, delete the local D1 state under `apps/api/.wrangler/` and run `npm run db:migrate:local` again. Production data is never copied locally.
::
