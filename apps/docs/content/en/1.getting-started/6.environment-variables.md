Wildcard distinguishes four kinds of configuration:

| Kind | Where it lives | Example |
| --- | --- | --- |
| **Binding** | `wrangler.jsonc` (versioned) | `DB`, `CONTACT_PHOTOS`, `CHAT_WORKFLOW`, `API` |
| **Variable** | `vars` in `wrangler.jsonc` (versioned, not secret). Installation-specific ones are empty in Git and resolved at release time | `HOME_FEED_ENABLED`, `BETTER_AUTH_URL` |
| **Secret** | Encrypted Worker secret at runtime; for most, an encrypted **CI secret** (Workers Builds build secret or GitHub Actions secret) that the release copies to runtime | `META_API_KEY`, `APNS_PRIVATE_KEY` |
| **Release input** | CI variable read by the release scripts (not secret) | `WILDCARD_API_URL`, `CLOUDFLARE_ACCOUNT_ID` |
| **Local only** | Ignored `apps/api/.dev.vars` | `ADMIN_LOCAL_ROUTES` |

::warning
Secret values never belong in Git, in build settings that are not encrypted, in documentation or in chat. Production secrets are set as encrypted Workers Builds variables or GitHub Actions secrets and uploaded by `scripts/release-worker.mjs`; do not use `wrangler secret put` to bypass the pipeline.
::

## API Worker (`wildcard-api`)

Configuration file: `apps/api/wrangler.jsonc` (account-neutral). Releases deploy the generated, ignored `apps/api/wrangler.release.json`, which adds the account, the real D1 ID and the installation values below. Types are generated into `apps/api/worker-configuration.d.ts` with `wrangler types --strict-vars false`.

### Bindings

| Name | Type | Required | Purpose |
| --- | --- | --- | --- |
| `DB` | D1 database `wildcard-db` | Yes | All data: auth, contacts, chats, groups, memory, settings |
| `CONTACT_PHOTOS` | R2 bucket `wildcard-contact-photos` | Yes | Private media: photos, attachments, voice, generated images, stickers, link-preview images |
| `CHAT_WORKFLOW` | Workflow `wildcard-chat`, class `ChatWorkflow` | Yes | Replies, group rounds, initiative, task work, For you |
| `ONBOARDING_WORKFLOW` | Workflow `wildcard-onboarding`, class `OnboardingWorkflow` | Yes | Onboarding circle and AI contact generation |
| `AI` | Workers AI | Yes (configured) | AI Gateway transport when `AI_GATEWAY_ID` is set; `@cf/baai/bge-m3` embeddings when semantic memory is on |
| Cron `* * * * *` | Trigger | Yes | Recovery, dispatch, retries and cleanup |

### Variables

| Name | Default in repo | Purpose | When missing or different |
| --- | --- | --- | --- |
| `BETTER_AUTH_URL` | `""`; set at release from `WILDCARD_API_URL`, otherwise `https://wildcard-api.<subdomain>.workers.dev` | Better Auth `baseURL`; base for MCP OAuth callbacks and signed push-photo URLs | Auth misconfigured. MCP OAuth rejects non-HTTPS or local hosts |
| `MCP_WEB_ORIGIN` | `""`; set at release from `WILDCARD_WEB_URL`, otherwise `https://wildcard-web.<subdomain>.workers.dev` | Exact web origin for the MCP OAuth completion redirect | Web OAuth connections fail; iOS uses `wildcard://` |
| `META_CHAT_MODEL` | `muse-spark-1.3` | Default model when no account preference applies; each request uses the account's `user.chat_model` | Invalid values fail with `MODEL_NOT_CONFIGURED` |
| `AI_GATEWAY_ID` | `""` | Routes Meta calls through the AI Gateway when non-empty | Empty means direct calls to `api.meta.ai` (current production setting) |
| `WEB_RESEARCH_ENABLED` | `"true"` | Web research tools in chats, groups and For you | Anything other than `"true"` disables research |
| `SEMANTIC_MEMORY_ENABLED` | `"false"` | Re-ranks memory with Workers AI embeddings | Lexical selection only |
| `HOME_FEED_ENABLED` | `"true"` | For you curation runs | Off: For you keeps quick access and agenda only. Also off without `META_API_KEY` |
| `SUPER_ADMIN_USER_IDS` | `""`; set at release from `WILDCARD_SUPER_ADMIN_USER_IDS` | Comma-separated user IDs allowed into the admin panel (not secret) | Empty: nobody can use the admin panel |

### Secrets

| Name | How it is set | Required | Purpose | When missing |
| --- | --- | --- | --- | --- |
| `BETTER_AUTH_SECRET` | Runtime only. Generated automatically by the first release (48 random bytes) and preserved afterwards | Yes | Signs sessions; HMAC for remote native claims and push-photo URLs; HKDF source of the AES-GCM key that encrypts MCP credentials | Shorter than 32 characters: auth and MCP encryption fail. **Rotating it signs everyone out and invalidates stored connector credentials** |
| `META_API_KEY` | Build secret, copied to runtime by the release (an existing runtime key is preserved if the build value is absent) | Yes (`secrets.required`) | Every Meta model call | Sends return `503`/`MODEL_NOT_CONFIGURED`; research, stickers, For you, initiative and task work are disabled |
| `ELEVENLABS_API_KEY` | Build secret → runtime | Optional | Contact voices and spoken replies (also needs the admin setting `voice_messages_enabled`) | Voice replies off |
| `APNS_PRIVATE_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC` | Build secrets → runtime, **all four together** | Optional | iOS push and remote timers/alarms. `APNS_TOPIC` is the app bundle ID | Push skipped; queued notifications expire; remote actions report "not configured" |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Build secrets → runtime, **all three together**. Generate with `node scripts/generate-vapid-keys.mjs` | Optional | Browser Web Push. `VAPID_SUBJECT` is a `mailto:` or `https:` contact | `GET /api/v1/push/web-key` returns `503`; the web switch shows "not configured" |

### Local only

| Name | Purpose |
| --- | --- |
| `ADMIN_LOCAL_ROUTES` | `true` mounts `/api/v1/admin/*` on the public app under `wrangler dev`, because a named entrypoint cannot be served locally. Never set it in `wrangler.jsonc` |

Values in `.dev.vars` override `vars` from `wrangler.jsonc` during `npm run dev`, so you can, for example, set `HOME_FEED_ENABLED=false` locally. Every value in `.dev.vars` reaches the local Worker, including optional secrets that are not in `secrets.required`.

### Runtime settings stored in D1

Some switches are not environment variables: super admins change them in the admin panel and they apply on the next request (table `app_setting`, migration 0059).

| Key | Default | Effect |
| --- | --- | --- |
| `registration_enabled` | `true` | Sign-up returns `403 REGISTRATION_CLOSED` when off; iOS and web show the early-access waitlist instead |
| `voice_messages_enabled` | `false` | Allows spoken contact replies (with `ELEVENLABS_API_KEY`) |

Each account also stores its model choice (`user.chat_model`: Standard `muse-spark-1.3` or Contributor `muse-spark-1.3-contributor`, with explicit consent).

## Web Worker (`wildcard-web`)

| Name | Kind | Purpose |
| --- | --- | --- |
| `API` | Service binding to `wildcard-api` (repeated under `previews`) | Same-origin `/api/v1/*` proxy. Without it the proxy returns `503` |
| `ASSETS` | Added by Nitro at build time | Static assets of the SPA |
| `runtimeConfig.apiOrigin` | Nuxt runtime config, `http://localhost:8787` | Used only in development |

The web Worker has **no variables and no secrets**.

## Admin Worker (`wildcard-admin`)

| Name | Kind | Purpose |
| --- | --- | --- |
| `API` | Service binding to `wildcard-api`, entrypoint `AdminAPI` | Allowlisted admin proxy (sign-in, sign-out, `/api/v1/admin/*`) |
| `runtimeConfig.apiOrigin` | Nuxt runtime config | Local API in development (requires `ADMIN_LOCAL_ROUTES=true` on the API) |

## Marketing site and docs (`wildcard-site`, `wildcard-docs`)

Static assets only: no script, binding, variable or secret. Installation-specific URLs of the marketing site are constants in `apps/site/app/utils/site.ts` (`url`, `appUrl`, `repositoryUrl`, `repositoryPublic`, `iosUrl`); the docs site URL is `siteUrl` in `apps/docs/nuxt.config.ts`.

## iOS build settings

| Setting | Purpose |
| --- | --- |
| `WILDCARD_API_URL` | API origin (app and notification service, Debug and Release), exposed as the Info.plist key `WildcardAPIURL`. Required: without it the app has no API |
| `WILDCARD_APP_GROUP` | App Group shared by the app and its three extensions |
| `WILDCARD_LINK_HOST` | Universal links host (`applinks:`) for authorized contact links, served by the web app's `apple-app-site-association` |
| `APNS_ENVIRONMENT` | `development` (Debug) or `production` (Release); sets `aps-environment` and tells the API which APNs host to use |

Secrets are never shipped to the iOS app.

## Release and CI variables

These are injected by the CI system and read by the release guards. Never set them locally to bypass the guards.

| Name | Purpose |
| --- | --- |
| `WORKERS_CI`, `WORKERS_CI_BRANCH`, `WORKERS_CI_COMMIT_SHA` | Workers Builds: `1`, the branch (must be the production branch) and the commit (must equal `git rev-parse HEAD`; used as the version tag) |
| `GITHUB_ACTIONS`, `GITHUB_REF_NAME`, `GITHUB_SHA` | The same for the GitHub Actions deploy workflow |
| `WILDCARD_PRODUCTION_BRANCH` | Optional override of the production branch (default `main`) |

Release inputs you set yourself, as Workers Builds build variables or GitHub Actions repository variables. All are optional; empty values count as unset.

| Name | Purpose |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Account to release to. Required only when the credential can see several accounts |
| `WILDCARD_API_URL` | Public API origin (`https://…`, no path) for `BETTER_AUTH_URL`, for example a custom domain |
| `WILDCARD_WEB_URL` | Public web origin for `MCP_WEB_ORIGIN` |
| `WILDCARD_SUPER_ADMIN_USER_IDS` | Comma-separated admin user IDs, applied on every API release |
| `WILDCARD_DB_NAME`, `WILDCARD_PHOTOS_BUCKET` | Other D1 database or R2 bucket names (defaults `wildcard-db`, `wildcard-contact-photos`) |
| `WILDCARD_DEPLOY` | GitHub Actions only: `true` turns the deploy workflow on |

GitHub Actions also needs the secret `CLOUDFLARE_API_TOKEN`; Workers Builds supplies its own credential. `npm run release:check`, `npm run infra:provision` and `npm run infra:ai-gateway` read the same inputs and use an optional `CLOUDFLARE_API_TOKEN`, otherwise the Wrangler login in memory.

## Local `.dev.vars` checklist

| Goal | Names |
| --- | --- |
| Minimum (auth, contacts) | `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET` (both created by `npm run setup`) |
| Replies and AI features | `META_API_KEY`, `META_CHAT_MODEL`, `AI_GATEWAY_ID=` |
| Admin panel | `ADMIN_LOCAL_ROUTES=true`, `SUPER_ADMIN_USER_IDS` |
| Voices | `ELEVENLABS_API_KEY` (`npm run setup` also enables voice messages locally) |
| Web Push | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` |
| APNs | `APNS_PRIVATE_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC` |
| MCP OAuth | `MCP_WEB_ORIGIN` (needs public HTTPS origins; not usable on localhost) |
