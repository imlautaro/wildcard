Wildcard runs entirely on Cloudflare's developer platform. There is **no KV, no Durable Objects, no Queues, no email service and no staging environment**.

## Service map

| Service | Resource in this installation | Used by | Why |
| --- | --- | --- | --- |
| [Workers](/en/cloudflare/workers) | `wildcard-api`, `wildcard-web`, `wildcard-admin`, `wildcard-site`, `wildcard-docs` | All | Serverless runtime for the API, the two Nuxt apps and the static sites |
| Static assets | `ASSETS` (web, admin), assets-only Workers (site, docs) | Web, admin, site, docs | Serve built front-end files from the edge |
| Service bindings | `API` → `wildcard-api`; `API` → `wildcard-api#AdminAPI` | Web, admin | Private Worker-to-Worker calls without a public hop or CORS |
| Named entrypoint | `AdminAPI` (`WorkerEntrypoint`) | API | An admin surface that is not reachable from the public API origin |
| [D1](/en/cloudflare/d1) | `wildcard-db` (binding `DB`) | API | Relational data, sessions, rate limits, FTS5 search, outboxes |
| [R2](/en/cloudflare/r2) | `wildcard-contact-photos` (binding `CONTACT_PHOTOS`) | API | Private media objects |
| [Workflows](/en/cloudflare/workflows-and-cron) | `wildcard-chat` (`ChatWorkflow`), `wildcard-onboarding` (`OnboardingWorkflow`) | API | Durable multi-step generation that survives restarts and closed apps |
| [Cron Triggers](/en/cloudflare/workflows-and-cron#the-minute-cron) | `* * * * *` | API | Recovery, dispatch, push retries and cleanup every minute |
| [Workers AI](/en/cloudflare/ai) | Binding `AI` | API | `@cf/baai/bge-m3` embeddings for optional semantic memory |
| [AI Gateway](/en/cloudflare/ai#ai-gateway) | Gateway `wildcard`, custom provider `meta` (optional, currently off) | API | Spend and metadata observability of Meta calls |
| Workers Observability | Logs (sampling 1) and traces (sampling 0.01 on the API) | API, web, admin | Debugging releases and failures |
| [Workers Builds](/en/cloudflare/workers-builds) | One project per Worker on `imlautaro/wildcard`, branch `main` | All | Automatic releases from pushed commits |
| Preview URLs | Branch Previews for `wildcard-web` | Web | Review a branch at `https://<branch>-wildcard-web.<subdomain>.workers.dev` |
| `workers.dev` | All Workers | All | Public origins (no custom domains are configured) |

## Required versus optional

::field-group
  :::field{name="Required" type="core"}
  API Worker, D1, R2, both Workflows, the minute Cron, the `BETTER_AUTH_SECRET` runtime secret, `META_API_KEY` for any model feature, and Workers Builds for releases.
  :::

  :::field{name="Required for the web app" type="web"}
  Web Worker with its `API` service binding and its own Workers Builds project.
  :::

  :::field{name="Optional" type="extras"}
  Admin Worker, marketing site, docs site, AI Gateway, semantic memory (Workers AI), web Previews, custom domains, Cloudflare Access in front of the admin panel.
  :::
::

## Plans and limits

- Better Auth password hashing consumes CPU time. Check your plan's Worker CPU limit before opening registration publicly.
- D1, R2, Workflows and Workers AI consume the account's quotas. None of the code changes billing settings.
- Workflows retain step results; the API stores only what it needs in D1 and cleans Workflow instances through the cleanup outbox when chats are deleted.

## Account-specific values

Replace these when you deploy to another account (see [Provisioning](/en/operations/provisioning)):

- `account_id` in every `wrangler.jsonc`.
- Worker `name`s if they are taken.
- D1 `database_name` and `database_id`, R2 `bucket_name`, Workflow `name`s.
- Origins: `BETTER_AUTH_URL`, `MCP_WEB_ORIGIN`, the iOS `WILDCARD_API_URL`, the site and docs URLs.
