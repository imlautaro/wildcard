## Configuration

```jsonc [apps/api/wrangler.jsonc]
"r2_buckets": [
  { "binding": "CONTACT_PHOTOS", "bucket_name": "wildcard-contact-photos" }
]
```

Despite its binding name, `CONTACT_PHOTOS` stores **all** private media. The bucket is private: `r2.dev` access is disabled and there are no public custom domains. Clients never receive bucket URLs; every object is streamed by an authorized API route that checks ownership, membership and the current version.

## Object key layout

| Key | Contents |
| --- | --- |
| `users/{owner}/{version}.jpg` | Account profile photo |
| `contacts/{owner}/{contactID}/{version}.jpg` | Contact portrait (shared contacts reuse the creator's object) |
| `groups/{groupID}/{version}.jpg` | Group photo |
| `attachments/{user}/{contact}/{turn}/{uuid}` | Private chat attachments (images and PDFs, up to 5 MiB) |
| `…/voice-a{attempt}-{i}` | Spoken reply bubbles |
| `…/sticker-a{attempt}` | Sent stickers |
| `…/image` | Images relayed between shared-contact participants |
| `group-attachments/{group}/{owner or agent}/…` | Group media |
| `generated/{imageID}/{index}.jpg` | Images generated by contacts (albums of up to three) |
| `users/{id}/stickers/{id}.png` | A person's sticker library |
| `contacts/{owner}/{agent}/stickers/{id}.png` | A contact's sticker library |
| `link-previews/{hash}` | Cached link-preview images |

Object keys that belong to chats are tracked in `chat_attachment_object` so they can be removed with their chat.

## Signed push-photo URLs

Notification avatars must be downloadable by the iOS notification service extension without a session. The API issues short-lived URLs under `/api/v1/push-photos/:id` signed with an HMAC derived from `BETTER_AUTH_SECRET`; the extension downloads photos only from that path on the configured API host.

## Cleanup

- Replacing a photo writes a new versioned key and deletes the previous one on a best-effort basis.
- Chat, contact, group and account deletion enqueue R2 deletions in the D1 `resource_cleanup` outbox, which the minute Cron retries.
- `cleanAttachments` removes orphaned attachment objects.

## Provisioning

The first API release creates the bucket (private) if it does not exist; `WILDCARD_PHOTOS_BUCKET` overrides its name. To check or create it beforehand:

```bash [Terminal]
npm run infra:provision              # show whether the bucket (and D1) exist
npm run infra:provision -- --create  # create missing D1 and R2 now
```

`npm run infra:photos` is an alias. Neither the script nor the release enables public access: `r2.dev` and public custom domains stay disabled. The release credential needs R2 edit in addition to its Workers, D1 and Workflows permissions. Locally, `wrangler dev` emulates the bucket under `apps/api/.wrangler/`; do not add `remote: true`.
