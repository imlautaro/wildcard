## Type checks

| Command | What it checks |
| --- | --- |
| `npm run typecheck` | Regenerates Worker binding types and runs TypeScript 7 on the API |
| `npm run typecheck:web` / `:admin` / `:site` | `nuxt prepare` plus `vue-tsc` on an aliased TypeScript 6 compiler |
| `npm run typecheck:docs` | `nuxt prepare` for the docs site |
| `npm run typecheck:lifecycle` | Types of the lifecycle test fixture |

Workers Builds runs the type check before every build, so a type error blocks the release.

## Lifecycle integration tests

```bash [Terminal]
npm run test:lifecycle
npm run test:memory-isolation --workspace @wildcard/api   # only the isolation: tests
```

`apps/api/tests/lifecycle.test.mjs` (Node's test runner) bundles `tests/lifecycle.worker.ts` with esbuild and runs it in **Miniflare** with local D1, R2 and stub Workflows, applying every migration in order. Outbound network calls return `503`, so no real provider is called. The suite covers chat and group clearing, the cleanup outbox with injected R2 and Workflow failures, retries, backoff and races, migration repairs, account, contact and admin deletion, and memory isolation and consent.

## Static checks

- `scripts/checks/*-sql-compile.*` compile the SQL statements of several features against SQLite.
- `scripts/checks/*.cjs` exercise pure logic such as group energy, receipts and publication.
- `node scripts/check-locales.mjs` validates English and Spanish messages for web and site: key parity, ICU compilation, placeholders and plural branches, and that every key used in source exists.
- The iOS project can be type-checked statically with `swiftc -typecheck` using the project's isolation flags.

## Live evaluations

`scripts/checks/conversation-style-live-eval.mjs`, `personality-live-eval.mjs` and `mini-app-eval.mjs` call the real Meta API (reading `META_API_KEY` from `.dev.vars`) with fictional data. They consume credits and are run only when explicitly requested.

## Policy

- The working agreements allow static validation at any time; builds and tests run when requested.
- Never use real account data to validate a feature. Never claim device behavior from static checks: each guide lists what remains to verify on devices.
