The API (`@wildcard/api`, Worker `wildcard-api`) is a Hono application that owns every piece of data and logic. Clients only ever talk to it.

## Source layout

| Path | Responsibility |
| --- | --- |
| `src/index.ts` | Worker entry: public `fetch`, `scheduled` Cron, Workflow classes, `AdminAPI` entrypoint |
| `src/app.ts` | Public Hono app: middleware, route mounting, 404 and error handlers |
| `src/lib/` | Auth (`auth.ts`, `auth-routes.ts`, `session.ts`), rate limiting, model preference, schema runtime, unread counts |
| `src/routes/` | `me`, `contacts`, `chats`, `push`, `schedules`, `sharing`, `debug-export` |
| `src/chat/` | Private chat engine: dispatch, `ChatWorkflow`, Meta client (`meta.ts`), context and tools (`context.ts`), presence, pacing, memory, semantic memory, initiative, learning, attachments, transcription, cleanup, export |
| `src/groups/` | Group routes, reply rounds and planning, energy, membership, requests, receipts, media, push |
| `src/contacts/` | AI contact generation, portraits, names, aliases, linked contacts |
| `src/personality/` | Personality profile, engine, relationships, acting director, conversation style |
| `src/onboarding/` | Onboarding routes and `OnboardingWorkflow` |
| `src/home/` | For you: curator, cards, comments, workflow |
| `src/tasks/`, `src/documents/`, `src/research/`, `src/monitors/`, `src/schedules/` | Agentic work features |

## HTTP surface

All routes are under `/api/v1`. Every response has `Cache-Control: no-store`. Unknown paths return `404 {"error":"Not found"}`; unexpected errors return `500` (`409` while a chat cleanup is in progress).

| Prefix | Purpose |
| --- | --- |
| `/auth/*` | Better Auth behind an allowlist: `sign-in/email`, `sign-up/email`, `sign-out`, `get-session` (16 KB body limit) |
| `/me` | Profile, `/model`, `/privacy`, `/photo`, `/debug-export`, `/mcp` (connections and OAuth start/refresh) |
| `/onboarding` | Options, state and start of the onboarding circle |
| `/contacts` | Contact CRUD, energy, initiative, voice, photo, archive, clear, plus `/generation`, `/sharing` and per-contact `/personality`, `/mini-apps`, `/tasks`, `/links`, `/documents`, `/learning`, `/stickers`, `/native-actions`, `/native-remote`, `/schedules`, `/mcp` |
| `/contacts/:id/chat` | `GET/POST /turns`, `PUT /read`, `POST /activity`, retry, attachments, `/transcriptions`, `/reactions`, `/media`, `/export` |
| `/groups` | Groups, invitations, messages, receipts, read state, agents, replies, media, tasks, documents, learning, mini apps, reactions, `/mcp` |
| `/home` | For you feed, badge, seen, refresh, topics, post comments |
| `/push` | `/device` (APNs), `/web-key`, `/web-device` (Web Push) |
| `/waitlist` | Public early-access waitlist: `GET` returns `{ registrationOpen }`, `POST` adds or updates an entry (five per IP per minute) |
| `/push-photos/:id` | HMAC-signed photos for notifications |
| `/native-execution` | Remote device execution receipts |
| `/voices`, `/stickers`, `/link-previews` | Voice catalog, sticker cutout and library, link cards |
| `/mcp/oauth` | Client metadata, launch and callback of MCP OAuth |
| `/admin/*` | Only through `AdminAPI` (or locally with `ADMIN_LOCAL_ROUTES=true`) |

## Authentication

- **Better Auth** (`better-auth/minimal`) with `basePath: '/api/v1/auth'`, the Drizzle adapter over D1 (`provider: 'sqlite'`), email and password (8–128 characters, no email verification yet).
- Sessions last **7 days** (refreshed daily). The `bearer({ requireSignature: true })` plugin returns a signed token in the `set-auth-token` header.
- The API reads **only** `Authorization: Bearer`; it has no cookie sessions. The web and admin proxies translate their `httpOnly` cookies into this header.
- `BETTER_AUTH_SECRET` must be at least 32 characters.
- Sign-up is gated by the admin setting `registration_enabled` (`403 REGISTRATION_CLOSED`). While it is closed, iOS and web offer the early-access waitlist (`/waitlist`, table `waitlist_entry`, migration 0101) instead.
- Better Auth's own rate limiter is disabled in favour of the D1-backed limiter keyed by `CF-Connecting-IP`.

::note
Password recovery and email ownership verification are not configured; there is no email service.
::

## Conventions

- **Owner scoping.** Every query filters by the session owner or a verified membership.
- **Idempotency.** Client-generated IDs (turns, uploads, research requests) make retries safe.
- **Atomic publication.** Multi-row changes use `env.DB.batch()` with conditional statements and revisions (`history_revision`, document revisions) instead of locks.
- **Bounded work.** Tool rounds, research, work turns, schedules and energy have explicit budgets ([agentic limits](/en/features/agentic-work#budgets-and-limits)).
- **Validation.** Inputs are validated by hand or with JSON Schema (`@cfworker/json-schema` for MCP); Zod runs in jitless mode for the libraries that need it.
- **Strictly public egress.** `global_fetch_strictly_public` plus a DNS-over-HTTPS private address guard for MCP.

## Adding an endpoint

1. Add the route to the relevant module under `src/` (or a new module mounted in `src/app.ts`), using the bearer session middleware of that module.
2. If you need storage, add a new migration in `apps/api/migrations` (see [Database migrations](/en/operations/database-migrations)).
3. Regenerate types if you changed `wrangler.jsonc`: `npm run types --workspace @wildcard/api`.
4. Run `npm run typecheck`.
5. Implement the client side on **both** iOS and web and update the affected guide in `docs/` ([Contributing](/en/operations/contributing)).
