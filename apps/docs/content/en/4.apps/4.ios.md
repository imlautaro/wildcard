The native app lives in `apps/ios` (`Wildcard.xcodeproj`). It is written in SwiftUI, targets **iOS 27.0** and uses **no third-party Swift packages**.

## Targets

| Target | Bundle ID suffix | Role |
| --- | --- | --- |
| `Wildcard` | `com.imlautaro.Wildcard` | The app |
| `WildcardNotificationService` | `.NotificationService` | Communication notifications with contact avatars; executes remote timers and alarms |
| `WildcardWidgets` | `.Widgets` | Contact widget and an AlarmKit Live Activity |
| `WildcardShare` | `.Share` | Share sheet into a chat draft |
| `WildcardTests`, `WildcardUITests` | — | Unit and UI tests |

`WildcardNativeShared` is a synchronized folder compiled into the app and all three extensions (not a framework). Extensions set compile conditions such as `WILDCARD_NOTIFICATION_EXTENSION`.

Swift settings: Swift 5 language mode, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and approachable concurrency on the app target, member import visibility enabled.

## Networking and session

- The API origin comes from the `WILDCARD_API_URL` build setting (Info.plist key `WildcardAPIURL`). The app talks to the API **directly**, not through the web proxy.
- Requests go to `api/v1/<path>` with `Authorization: Bearer <token>` over an ephemeral `URLSession` with no cookies and no cache.
- The token from `set-auth-token` is stored in the Keychain (`<bundleID>.auth`, account `session`, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`) and restored at launch. An expired session clears it.

## Caching

The project rule is **cache by default** (`AGENTS.md`, `docs/caching.md`):

- `NavigationSnapshotCache<Value>`: a main-actor LRU (8 entries) for secondary screens, reused synchronously on navigation and revalidated in the background.
- `PrivateImageCache`: account-scoped memory plus protected disk cache (`PrivateImages-v1`) for avatars, chat images, voice audio and link-preview images. Keys include account, access context, resource identity and version.
- Conversation stores keep loaded chats; `ConversationSync` polls the visible chat every second; the home shell refreshes every 15 seconds.

## Push notifications

- `aps-environment` comes from `APNS_ENVIRONMENT` (`development` in Debug, `production` in Release) and is sent to the API so it picks the sandbox or production APNs host.
- The device token is registered with `PUT /api/v1/push/device` and removed on sign-out.
- The notification service extension builds communication notifications (`INSendMessageIntent`) and downloads avatars only from `/api/v1/push-photos/` on the configured host.
- Unread counts persist on the server and appear on rows, the Chats tab and the app icon badge.

## System integrations

- **App Intents and Shortcuts**: open a contact, draft a message, Action button shortcuts (`Native/NativeIntents.swift`).
- **Widgets**: contact widget (`WildcardContacts`) and an AlarmKit Live Activity.
- **Universal links**: `applinks:$(WILDCARD_LINK_HOST)` for authorized contact links; the web app serves `/.well-known/apple-app-site-association`.
- **Native experiments**: timers, alarms, Calendar and Reminders requested by a contact, with per-device permissions and receipts.
- **App Group** (`WILDCARD_APP_GROUP`) shared by the app and its extensions.

## Localization

English and Spanish with String Catalogs (`Localizable.xcstrings` per target, `InfoPlist.xcstrings`, `AppShortcuts.xcstrings`), English as the key. There is no in-app override: Account → Language opens the system per-app language setting.

## Configuring for your own account

1. Select your signing team and replace bundle identifiers (the extension IDs must extend the app ID).
2. Set `WILDCARD_API_URL` on the app and notification service targets (Debug and Release).
3. Replace `WILDCARD_APP_GROUP` and `WILDCARD_LINK_HOST`, and enable App Groups, Associated Domains, Push Notifications and Communication Notifications for the App IDs.
4. Create an APNs key and configure the `APNS_*` build secrets of the API project, with `APNS_TOPIC` equal to the app bundle ID.

::note
API releases do not update installed apps. Build and distribute the iOS app separately.
::
