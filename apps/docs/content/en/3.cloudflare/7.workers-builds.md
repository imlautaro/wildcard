Production releases are **automatic**: every Worker has its own Workers Builds project connected to the GitHub repository and the `main` branch. A push to `main` builds and deploys the Workers whose watched paths changed. No project needs edits to versioned files: the API release resolves the account, D1, R2 and origins at release time (see [How it works](/en/self-host/how-it-works#what-the-release-resolves)). For the API and the web app, the opt-in GitHub Actions workflow is an alternative; use only one of them per Worker.

## Projects

| Worker | Root | Build command | Deploy command | Previews |
| --- | --- | --- | --- | --- |
| `wildcard-api` | `/` | `npm ci && npm run typecheck` | `npm run release:ci` | Disabled |
| `wildcard-web` | `/` | `npm ci && npm run typecheck:web && npm run build:web` | `npm run release:web` | Enabled: `npm run preview:web` |
| `wildcard-admin` | `/` | `npm ci && npm run typecheck:admin && npm run build:admin` | `npm run release:admin` | Disabled |
| `wildcard-site` | `/` | `npm ci && npm run typecheck:site && npm run build:site` | `npm run release:site` | Disabled |
| `wildcard-docs` | `/` | `npm ci && npm run typecheck:docs && npm run build:docs` | `npm run release:docs` | Disabled |

The build root is always `/` because npm workspaces use the root lockfile and Nuxt resolves the shared layer from there.

## Watch paths

Each project only builds when its inputs change. `docs/workers-build-paths.json` is the reference for the dashboard settings (it is not read by Wrangler).

| Worker | Include paths (in addition to the root build inputs) |
| --- | --- |
| `wildcard-api` | `apps/api/*`, `shared/*`, `scripts/release-worker.mjs`, `scripts/lib/*`, `apps/web/wrangler.jsonc` (the web Worker name sets the default `MCP_WEB_ORIGIN`) |
| `wildcard-web` | `apps/web/*`, `packages/ui/*`, `shared/*`, `scripts/release-web.mjs`, `scripts/preview-web.mjs`, `scripts/lib/*` |
| `wildcard-admin` | `apps/admin/*`, `packages/ui/*`, `scripts/release-admin.mjs`, `scripts/lib/*` |
| `wildcard-site` | `apps/site/*`, `packages/ui/*`, `scripts/release-site.mjs`, `scripts/lib/*` |
| `wildcard-docs` | `apps/docs/*`, `scripts/release-docs.mjs`, `scripts/lib/*` |

Root build inputs watched by every project: `package.json`, `package-lock.json`, `.nvmrc`, `.npmrc`, `.gitignore`. A lockfile change therefore rebuilds every Worker.

Cloudflare's watch-path `*` matches nested directories (it is not a filesystem glob). Filters are bypassed for pushes with no changed files, 3,000 or more files or 20 or more commits.

## Release guards

Every release script (`scripts/release-*.mjs`) refuses to run unless:

1. it runs in CI: `WORKERS_CI=1` (Workers Builds) or `GITHUB_ACTIONS=true` (the GitHub Actions deploy workflow);
2. the branch (`WORKERS_CI_BRANCH` or `GITHUB_REF_NAME`) equals the production branch (`main`, or `WILDCARD_PRODUCTION_BRANCH`);
3. the commit (`WORKERS_CI_COMMIT_SHA` or `GITHUB_SHA`) is a full SHA equal to `git rev-parse HEAD`;
4. the checkout is clean (`git status --porcelain` is empty).

The guards live in `scripts/lib/release-guard.mjs`. `npm run release:check` reports which of them a real release would stop at without stopping.

It then deploys with `wrangler deploy --tag <commit SHA>`, so the active version can always be traced to its source commit. The first build after connecting a repository may lack source metadata and stop safely; the next push releases.

## Build secrets

Only the API project has build secrets: `META_API_KEY` and the optional `ELEVENLABS_API_KEY`, `APNS_*` and `VAPID_*` values, all stored as **encrypted** build variables. Plain build variables are needed only to override defaults: `CLOUDFLARE_ACCOUNT_ID` (when the credential sees several accounts), `WILDCARD_API_URL`, `WILDCARD_WEB_URL`, `WILDCARD_SUPER_ADMIN_USER_IDS`, `WILDCARD_DB_NAME` and `WILDCARD_PHOTOS_BUCKET`. Empty values count as unset. The API release copies them to runtime secrets through a temporary owner-only file passed to `wrangler deploy --secrets-file`, deleted in a `finally` block. See [Releases](/en/operations/releases).

## Credentials

| Project | Minimum permissions |
| --- | --- |
| API | Workers Scripts edit, D1 edit, Workflows edit, R2 edit (the first release creates the bucket), account read |
| Web, admin, site, docs | Workers Scripts edit and account read |

Select an existing, suitably scoped credential in the dashboard; never commit its value.

## Checking a release

```bash [Terminal]
# Check runs posted by Workers Builds on a commit
gh api repos/<owner>/<repo>/commits/<sha>/check-runs \
  --jq '.check_runs[] | "\(.name)|\(.status)|\(.conclusion)"'

# Active versions of a Worker and their tags (tag = commit SHA)
npx wrangler deployments list --config apps/site/wrangler.jsonc
```
