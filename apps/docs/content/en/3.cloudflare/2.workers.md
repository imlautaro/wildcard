## The five Workers

| Worker | Config | Type | Bindings |
| --- | --- | --- | --- |
| `wildcard-api` | `apps/api/wrangler.jsonc` | Script (`src/index.ts`) | `DB`, `CONTACT_PHOTOS`, `CHAT_WORKFLOW`, `ONBOARDING_WORKFLOW`, `AI`, Cron |
| `wildcard-web` | `apps/web/wrangler.jsonc` → `.output/server/wrangler.json` | Nitro `cloudflare_module` | `API` (service), `ASSETS` |
| `wildcard-admin` | `apps/admin/wrangler.jsonc` → `.output/server/wrangler.json` | Nitro `cloudflare_module` | `API` (service, entrypoint `AdminAPI`), `ASSETS` |
| `wildcard-site` | `apps/site/wrangler.jsonc` | Static assets only | none |
| `wildcard-docs` | `apps/docs/wrangler.jsonc` | Static assets only | none |

All Workers use `compatibility_date: "2026-10-26"`. The script Workers enable `nodejs_compat`; the API also enables `global_fetch_strictly_public`, so `fetch` from the API can only reach public addresses (important for link previews, page monitors and MCP egress).

## API entry points

`apps/api/src/index.ts` exports:

```ts [apps/api/src/index.ts (simplified)]
export { OnboardingWorkflow } from './onboarding/workflow';
export { ChatWorkflow } from './chat/workflow';

// Reachable only through a service binding with entrypoint "AdminAPI".
export class AdminAPI extends WorkerEntrypoint<Env> {
  fetch(request: Request) { return adminApp.fetch(request, this.env, this.ctx); }
}

export default {
  fetch: app.fetch,            // public Hono app: /api/v1/*
  scheduled(event, env, ctx) { /* minute Cron duties, each in ctx.waitUntil */ },
};
```

## Service bindings

The web and admin Workers never call the API over the public internet. Their Nitro server route `server/api/v1/[...path].ts`:

1. Rejects dot segments and encoded separators (`404`) and non-GET cross-site requests (`403`, checked with `Sec-Fetch-Site` and `Origin`).
2. Rebuilds the upstream request from an allowlist of headers: `Accept`, `Content-Type`, `Authorization: Bearer <token from the cookie>` and `CF-Connecting-IP` (so per-IP rate limits still apply in the API).
3. Calls `env.API.fetch(new Request('https://wildcard-api.internal' + path, …))`.
4. Returns only allowlisted response headers and adds `Cache-Control: no-store`.
5. On sign-in or sign-up, stores the `set-auth-token` header in an `httpOnly` cookie and returns only `{ user }`.

| Cookie | Worker | Attributes |
| --- | --- | --- |
| `__Host-wildcard_session` | Web | `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, 7 days |
| `__Host-wildcard_admin_session` | Admin | Same attributes |

In development the cookie names drop the `__Host-` prefix and the proxy calls `http://localhost:8787` with a normal `fetch`.

### The `AdminAPI` entrypoint

The admin binding targets `entrypoint: "AdminAPI"`. On the public API origin, `/api/v1/admin/*` returns `404`; only the admin Worker can reach the admin routes. The admin proxy additionally forwards only `POST /api/v1/auth/sign-in/email`, `POST /api/v1/auth/sign-out` and `/api/v1/admin/*`.

## Static assets

- **Web and admin**: Nitro adds an `ASSETS` binding and writes `.output/server/wrangler.json` with `main` and `assets`. Releases deploy that generated file, never the source `wrangler.jsonc` directly.
- **Site and docs**: assets-only Workers serve `.output/public` with `html_handling: "auto-trailing-slash"` and `not_found_handling: "404-page"`. The docs also ship a `_redirects` file that sends `/` to `/en`.

## Security headers

The web app sets, on every route: `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY` and `Permissions-Policy: camera=(), microphone=(self), geolocation=()`. The admin panel also sends `X-Robots-Tag` (noindex) and disables the microphone. All API responses carry `Cache-Control: no-store`.

## Observability

| Worker | Logs | Traces | Query strings |
| --- | --- | --- | --- |
| API | Enabled, head sampling 1 | Enabled, head sampling 0.01 | Redacted |
| Web, admin | Enabled, head sampling 1 | — | Redacted |

The API logs sanitized event names (for example `push_accepted`, `push_delivery_deferred`) and never conversation content, tokens or secrets.

## Origins and Previews

- Every Worker has `workers_dev: true`. The reference installation serves `https://<worker>.imlautaro.workers.dev`; a fork gets its own account's subdomain, which the API release uses for the default origins.
- `preview_urls` is on for API, web and admin, but **only the web project builds branch Previews**. Web's `wrangler.jsonc` has a `previews` block repeating the `API` binding; a Preview therefore talks to the **production** API and data.
- The API and admin have no `previews` block: an API Preview would start without its secrets and would need decisions about D1 and Workflows.
