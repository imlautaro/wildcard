Wildcard distingue cuatro tipos de configuración:

| Tipo | Dónde vive | Ejemplo |
| --- | --- | --- |
| **Binding** | `wrangler.jsonc` (versionado) | `DB`, `CONTACT_PHOTOS`, `CHAT_WORKFLOW`, `API` |
| **Variable** | `vars` en `wrangler.jsonc` (versionada, no secreta). Las específicas de cada instalación están vacías en Git y se resuelven en el momento del release | `HOME_FEED_ENABLED`, `BETTER_AUTH_URL` |
| **Secreto** | Secreto cifrado del Worker en tiempo de ejecución; en la mayoría de los casos, un **secreto de CI** cifrado (secreto de compilación de Workers Builds o secreto de GitHub Actions) que el release copia al runtime | `META_API_KEY`, `APNS_PRIVATE_KEY` |
| **Entrada del release** | Variable de CI que leen los scripts de release (no secreta) | `WILDCARD_API_URL`, `CLOUDFLARE_ACCOUNT_ID` |
| **Solo local** | `apps/api/.dev.vars` ignorado | `ADMIN_LOCAL_ROUTES` |

::warning
Los valores secretos nunca deben estar en Git, en ajustes de compilación sin cifrar, en la documentación ni en un chat. Los secretos de producción se definen como variables cifradas de Workers Builds o secretos de GitHub Actions y los sube `scripts/release-worker.mjs`; no uses `wrangler secret put` para saltarte el pipeline.
::

## Worker de API (`wildcard-api`)

Archivo de configuración: `apps/api/wrangler.jsonc` (neutral respecto de la cuenta). Los releases despliegan el archivo generado e ignorado `apps/api/wrangler.release.json`, que agrega la cuenta, el ID real de D1 y los valores de la instalación que se indican abajo. Los tipos se generan en `apps/api/worker-configuration.d.ts` con `wrangler types --strict-vars false`.

### Bindings

| Nombre | Tipo | Obligatorio | Propósito |
| --- | --- | --- | --- |
| `DB` | Base de datos D1 `wildcard-db` | Sí | Todos los datos: autenticación, contactos, chats, grupos, memoria, ajustes |
| `CONTACT_PHOTOS` | Bucket R2 `wildcard-contact-photos` | Sí | Multimedia privada: fotos, adjuntos, voz, imágenes generadas, stickers, imágenes de vista previa de enlaces |
| `CHAT_WORKFLOW` | Workflow `wildcard-chat`, clase `ChatWorkflow` | Sí | Respuestas, rondas de grupo, iniciativa, trabajo de tareas, Para ti |
| `ONBOARDING_WORKFLOW` | Workflow `wildcard-onboarding`, clase `OnboardingWorkflow` | Sí | Círculo de onboarding y generación de contactos con IA |
| `AI` | Workers AI | Sí (configurado) | Transporte del AI Gateway cuando `AI_GATEWAY_ID` está definido; embeddings `@cf/baai/bge-m3` cuando la memoria semántica está activada |
| Cron `* * * * *` | Trigger | Sí | Recuperación, despacho, reintentos y limpieza |

### Variables

| Nombre | Valor por defecto en el repo | Propósito | Cuando falta o es distinta |
| --- | --- | --- | --- |
| `BETTER_AUTH_URL` | `""`; el release la define desde `WILDCARD_API_URL` o, si no está, `https://wildcard-api.<subdomain>.workers.dev` | `baseURL` de Better Auth; base para los callbacks de MCP OAuth y las URLs firmadas de fotos de push | Autenticación mal configurada. MCP OAuth rechaza hosts que no son HTTPS o que son locales |
| `MCP_WEB_ORIGIN` | `""`; el release la define desde `WILDCARD_WEB_URL` o, si no está, `https://wildcard-web.<subdomain>.workers.dev` | Origen web exacto para la redirección de finalización de MCP OAuth | Las conexiones OAuth desde la web fallan; iOS usa `wildcard://` |
| `META_CHAT_MODEL` | `muse-spark-1.3` | Modelo por defecto cuando no aplica ninguna preferencia de la cuenta; cada solicitud usa el `user.chat_model` de la cuenta | Los valores no válidos fallan con `MODEL_NOT_CONFIGURED` |
| `AI_GATEWAY_ID` | `""` | Enruta las llamadas a Meta por el AI Gateway cuando no está vacía | Vacía significa llamadas directas a `api.meta.ai` (configuración actual de producción) |
| `WEB_RESEARCH_ENABLED` | `"true"` | Herramientas de investigación web en chats, grupos y Para ti | Cualquier valor distinto de `"true"` desactiva la investigación |
| `SEMANTIC_MEMORY_ENABLED` | `"false"` | Reordena la memoria con embeddings de Workers AI | Solo selección léxica |
| `HOME_FEED_ENABLED` | `"true"` | Se ejecuta la curación de Para ti | Desactivada: Para ti conserva solo el acceso rápido y la agenda. También queda desactivada sin `META_API_KEY` |
| `SUPER_ADMIN_USER_IDS` | `""`; el release la define desde `WILDCARD_SUPER_ADMIN_USER_IDS` | IDs de usuario separados por comas con acceso al panel de administración (no es secreta) | Vacía: nadie puede usar el panel de administración |

### Secretos

| Nombre | Cómo se define | Obligatorio | Propósito | Cuando falta |
| --- | --- | --- | --- | --- |
| `BETTER_AUTH_SECRET` | Solo en runtime. Lo genera automáticamente el primer release (48 bytes aleatorios) y se conserva después | Sí | Firma las sesiones; HMAC para los claims nativos remotos y las URLs de fotos de push; fuente HKDF de la clave AES-GCM que cifra las credenciales de MCP | Con menos de 32 caracteres: fallan la autenticación y el cifrado de MCP. **Rotarlo cierra la sesión de todos e invalida las credenciales de conectores guardadas** |
| `META_API_KEY` | Secreto de compilación, copiado al runtime por el release (se conserva una clave de runtime existente si falta el valor de compilación) | Sí (`secrets.required`) | Todas las llamadas a modelos de Meta | Los envíos devuelven `503`/`MODEL_NOT_CONFIGURED`; la investigación, los stickers, Para ti, la iniciativa y el trabajo de tareas quedan desactivados |
| `ELEVENLABS_API_KEY` | Secreto de compilación → runtime | Opcional | Voces de los contactos y respuestas habladas (también requiere el ajuste de administración `voice_messages_enabled`) | Respuestas de voz desactivadas |
| `APNS_PRIVATE_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC` | Secretos de compilación → runtime, **los cuatro juntos** | Opcional | Push de iOS y temporizadores/alarmas remotos. `APNS_TOPIC` es el bundle ID de la app | Se omite el push; las notificaciones en cola expiran; las acciones remotas informan "not configured" |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Secretos de compilación → runtime, **los tres juntos**. Genéralos con `node scripts/generate-vapid-keys.mjs` | Opcional | Web Push del navegador. `VAPID_SUBJECT` es un contacto `mailto:` o `https:` | `GET /api/v1/push/web-key` devuelve `503`; el interruptor de la web muestra "not configured" |

### Solo local

| Nombre | Propósito |
| --- | --- |
| `ADMIN_LOCAL_ROUTES` | `true` monta `/api/v1/admin/*` en la app pública bajo `wrangler dev`, porque un entrypoint con nombre no se puede servir en local. Nunca la definas en `wrangler.jsonc` |

Los valores de `.dev.vars` sobrescriben los `vars` de `wrangler.jsonc` durante `npm run dev`, así que puedes, por ejemplo, definir `HOME_FEED_ENABLED=false` en local. Todos los valores de `.dev.vars` llegan al Worker local, incluidos los secretos opcionales que no están en `secrets.required`.

### Ajustes de runtime guardados en D1

Algunos interruptores no son variables de entorno: los super admins los cambian en el panel de administración y se aplican en la siguiente solicitud (tabla `app_setting`, migración 0059).

| Clave | Valor por defecto | Efecto |
| --- | --- | --- |
| `registration_enabled` | `true` | El registro devuelve `403 REGISTRATION_CLOSED` cuando está desactivado |
| `voice_messages_enabled` | `false` | Permite respuestas habladas de los contactos (con `ELEVENLABS_API_KEY`) |

Cada cuenta también guarda su elección de modelo (`user.chat_model`: Estándar `muse-spark-1.3` o Contributor `muse-spark-1.3-contributor`, con consentimiento explícito).

## Worker web (`wildcard-web`)

| Nombre | Tipo | Propósito |
| --- | --- | --- |
| `API` | Service binding a `wildcard-api` (repetido bajo `previews`) | Proxy `/api/v1/*` del mismo origen. Sin él, el proxy devuelve `503` |
| `ASSETS` | Lo agrega Nitro en tiempo de compilación | Static assets de la SPA |
| `runtimeConfig.apiOrigin` | Runtime config de Nuxt, `http://localhost:8787` | Se usa solo en desarrollo |

El Worker web **no tiene variables ni secretos**.

## Worker de administración (`wildcard-admin`)

| Nombre | Tipo | Propósito |
| --- | --- | --- |
| `API` | Service binding a `wildcard-api`, entrypoint `AdminAPI` | Proxy de administración con lista de rutas permitidas (inicio de sesión, cierre de sesión, `/api/v1/admin/*`) |
| `runtimeConfig.apiOrigin` | Runtime config de Nuxt | API local en desarrollo (requiere `ADMIN_LOCAL_ROUTES=true` en la API) |

## Sitio de marketing y documentación (`wildcard-site`, `wildcard-docs`)

Solo static assets: sin script, binding, variable ni secreto. Las URLs específicas de cada instalación del sitio de marketing son constantes en `apps/site/app/utils/site.ts` (`url`, `appUrl`, `repositoryUrl`, `repositoryPublic`, `iosUrl`); la URL del sitio de documentación es `siteUrl` en `apps/docs/nuxt.config.ts`.

## Build settings de iOS

| Ajuste | Propósito |
| --- | --- |
| `WILDCARD_API_URL` | Origen de la API (app y servicio de notificaciones, Debug y Release), expuesto como la clave de Info.plist `WildcardAPIURL`. Obligatorio: sin él la app no tiene API |
| `WILDCARD_APP_GROUP` | App Group compartido por la app y sus tres extensiones |
| `WILDCARD_LINK_HOST` | Host de los universal links (`applinks:`) para los enlaces de contactos autorizados, servido por el `apple-app-site-association` de la app web |
| `APNS_ENVIRONMENT` | `development` (Debug) o `production` (Release); define `aps-environment` e indica a la API qué host de APNs usar |

Los secretos nunca se incluyen en la app iOS.

## Variables de release y CI

Las inyecta el sistema de CI y las leen las protecciones del release. Nunca las definas en local para saltarte las protecciones.

| Nombre | Propósito |
| --- | --- |
| `WORKERS_CI`, `WORKERS_CI_BRANCH`, `WORKERS_CI_COMMIT_SHA` | Workers Builds: `1`, la rama (debe ser la rama de producción) y el commit (debe ser igual a `git rev-parse HEAD`; se usa como etiqueta de versión) |
| `GITHUB_ACTIONS`, `GITHUB_REF_NAME`, `GITHUB_SHA` | Lo mismo para el workflow de deploy de GitHub Actions |
| `WILDCARD_PRODUCTION_BRANCH` | Sobrescritura opcional de la rama de producción (por defecto `main`) |

Entradas del release que defines tú, como variables de build de Workers Builds o variables del repositorio en GitHub Actions. Todas son opcionales; los valores vacíos cuentan como no definidos.

| Nombre | Propósito |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Cuenta de destino del release. Solo es obligatoria cuando la credencial puede ver varias cuentas |
| `WILDCARD_API_URL` | Origen público de la API (`https://…`, sin ruta) para `BETTER_AUTH_URL`, por ejemplo un dominio personalizado |
| `WILDCARD_WEB_URL` | Origen web público para `MCP_WEB_ORIGIN` |
| `WILDCARD_SUPER_ADMIN_USER_IDS` | IDs de usuario de administración separados por comas; se aplican en cada release de la API |
| `WILDCARD_DB_NAME`, `WILDCARD_PHOTOS_BUCKET` | Otros nombres de base de datos D1 o de bucket de R2 (por defecto `wildcard-db`, `wildcard-contact-photos`) |
| `WILDCARD_DEPLOY` | Solo GitHub Actions: `true` activa el workflow de deploy |

GitHub Actions también necesita el secreto `CLOUDFLARE_API_TOKEN`; Workers Builds aporta su propia credencial. `npm run release:check`, `npm run infra:provision` y `npm run infra:ai-gateway` leen las mismas entradas y usan un `CLOUDFLARE_API_TOKEN` opcional; si no está, se usa en memoria el inicio de sesión de Wrangler.

## Checklist del `.dev.vars` local

| Objetivo | Nombres |
| --- | --- |
| Mínimo (autenticación, contactos) | `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET` (ambos creados por `npm run setup`) |
| Respuestas y funcionalidades de IA | `META_API_KEY`, `META_CHAT_MODEL`, `AI_GATEWAY_ID=` |
| Panel de administración | `ADMIN_LOCAL_ROUTES=true`, `SUPER_ADMIN_USER_IDS` |
| Voces | `ELEVENLABS_API_KEY` (`npm run setup` también habilita los mensajes de voz en local) |
| Web Push | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` |
| APNs | `APNS_PRIVATE_KEY`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_TOPIC` |
| MCP OAuth | `MCP_WEB_ORIGIN` (requiere orígenes HTTPS públicos; no se puede usar en localhost) |
