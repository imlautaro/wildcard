## Carpetas

```text
.
├── apps/
│   ├── api/            # @wildcard/api   – Worker de API Hono (wildcard-api)
│   │   ├── src/        # Rutas, Workflows, tareas de Cron, módulos de funcionalidades
│   │   ├── migrations/ # 93 migraciones de D1 escritas a mano (0001 … 0093)
│   │   ├── tests/      # Pruebas de ciclo de vida con Miniflare
│   │   └── wrangler.jsonc
│   ├── web/            # @wildcard/web   – SPA en Nuxt 4 + proxy de API (wildcard-web)
│   ├── admin/          # @wildcard/admin – Panel de super admin (wildcard-admin)
│   ├── site/           # @wildcard/site  – Sitio de marketing estático (wildcard-site)
│   ├── docs/           # @wildcard/docs  – Esta documentación (wildcard-docs)
│   └── ios/            # Proyecto de Xcode: app, extensiones, pruebas
├── packages/
│   └── ui/             # @wildcard/ui – Capa de Nuxt: tokens, componentes App*, íconos
├── shared/             # TypeScript compartido por la API y la app web
├── scripts/            # Scripts de release, aprovisionamiento, configuración local y validación
│   └── checks/         # Scripts de compilación estática de SQL y evaluación en vivo
├── docs/               # Guías detalladas de funcionalidades e infraestructura (fuente de verdad)
├── AGENTS.md           # Acuerdos de trabajo
├── package.json        # Workspaces y scripts de la raíz
└── package-lock.json   # El único lockfile para todos los workspaces
```

## Workspaces

El `package.json` de la raíz declara `apps/api`, `apps/web`, `apps/admin`, `apps/site`, `apps/docs` y `packages/ui`. Todas las dependencias de JavaScript se instalan desde el **lockfile de la raíz** con `npm ci`; los workspaces nunca tienen su propio lockfile. Se requiere Node.js 24 o posterior (`engines` y `.nvmrc`).

El proyecto de iOS no es un workspace; abre `apps/ios/Wildcard.xcodeproj` en Xcode.

## Scripts de la raíz

| Script | Qué hace |
| --- | --- |
| `npm run dev:all` | API y app web a la vez |
| `npm run dev` | API con `wrangler dev` en `http://localhost:8787` (sin iniciar sesión en Cloudflare, con cron local) |
| `npm run dev:web` | App web en `http://localhost:3000` (hace proxy hacia la API local) |
| `npm run dev:admin` | Panel de administración en `http://localhost:3001` |
| `npm run dev:site` | Sitio de marketing en `http://localhost:3002` |
| `npm run dev:docs` | Esta documentación en `http://localhost:3004` |
| `npm run typecheck` | Regenera los tipos del Worker (`wrangler types`) y ejecuta `tsc` para la API |
| `npm run typecheck:web` / `:admin` / `:site` / `:docs` | `nuxt prepare` más `vue-tsc` (docs: `nuxt prepare`) |
| `npm run build` | Bundle de la API con `wrangler deploy --dry-run` (no publica) |
| `npm run build:web` / `:admin` | `nuxt build` en `.output/` con un `wrangler.json` generado |
| `npm run build:site` / `:docs` | `nuxt generate` en `.output/public` |
| `npm run setup` | Crea `apps/api/.dev.vars` (secreto de autenticación, claves de API desde `.env`) y aplica las migraciones locales. Alias: `npm run auth:setup:local` |
| `npm run db:migrate:local` | Aplica las migraciones pendientes a la D1 local |
| `npm run db:migrate:remote` | Aplica las migraciones pendientes a la D1 de **producción** (los releases ya lo hacen) |
| `npm run test:lifecycle` | Pruebas de integración del ciclo de vida en Miniflare con datos ficticios |
| `npm run infra:provision` | Crea o reutiliza la base de datos D1 y actualiza el binding |
| `npm run infra:photos` | Verifica (o, con `-- --create`, crea) el bucket R2 privado |
| `npm run infra:ai-gateway` | Verifica (o, con `-- --create`, crea) el AI Gateway opcional |
| `npm run release:ci` / `:web` / `:admin` / `:site` / `:docs` | Scripts de release; solo se ejecutan dentro de Workers Builds |
| `npm run preview:web` | Despliega una Preview de rama de la app web |
| `npm run ios` | Abre el proyecto de Xcode |

## Carpeta de scripts

| Script | Propósito |
| --- | --- |
| `release-worker.mjs` | Release de la API: protecciones, migraciones remotas de D1, inicialización de secretos, deploy etiquetado |
| `release-web.mjs`, `release-admin.mjs` | Despliegan el `.output/server/wrangler.json` generado por Nitro |
| `release-site.mjs`, `release-docs.mjs` | Despliegan los Workers de static assets |
| `preview-web.mjs` | `wrangler preview` para ramas que no son de producción |
| `setup-local.mjs` | Configuración local: comprobación de Node.js, `.dev.vars` de acceso exclusivo para el dueño, migraciones locales |
| `dev-api.mjs`, `dev-all.mjs` | Ejecutor local de la API (configuración de Wrangler derivada y cron) y ejecutor combinado de API + web |
| `generate-vapid-keys.mjs` | Imprime un nuevo juego de claves VAPID para Web Push |
| `provision-d1.mjs`, `provision-photos.mjs`, `provision-ai-gateway.mjs` | Aprovisionamiento idempotente de recursos |
| `check-locales.mjs` | Valida las traducciones de la web y el sitio (claves, placeholders, plurales, uso) |
| `export-connector-logos.mjs` | Exporta los logos de los conectores MCP |
| `checks/*` | Verificaciones de compilación estática de SQL y evaluaciones de modelos en vivo |
