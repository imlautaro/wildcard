## Requisitos previos

- **Node.js 24 o posterior** y npm (el repositorio fija `24` en `.nvmrc`).
- macOS con **Xcode 27.1 o posterior** para la app iOS (deployment target iOS 27.0).
- No necesitas una cuenta de Cloudflare ni iniciar sesión para la emulación local: Wrangler emula D1, R2 y Workflows en tu máquina.
- Opcional: una clave de la Meta Model API con acceso a Muse Spark 1.3 para generar respuestas en local. Las llamadas consumen créditos reales.

## Primera ejecución

::steps{level="3"}

### Instala las dependencias

Desde la raíz del repositorio, siempre con el lockfile de la raíz:

```bash [Terminal]
npm ci
```

### Crea el secreto de autenticación y la base de datos locales

```bash [Terminal]
npm run auth:setup:local
```

Esto escribe un `apps/api/.dev.vars` ignorado y de acceso exclusivo para el dueño, con `BETTER_AUTH_URL=http://localhost:8787` y un `BETTER_AUTH_SECRET` aleatorio, y luego aplica **todas** las migraciones de `apps/api/migrations` a la D1 local de Wrangler (guardada bajo `.wrangler/`, ignorada por Git). Un `.dev.vars` existente nunca se sobrescribe.

### Inicia la API

```bash [Terminal]
npm run dev
```

Wrangler sirve la API en `http://localhost:8787`, incluidos los Workflows y un bucket R2 emulado. Las rutas desconocidas devuelven `404` en JSON y `GET /api/v1/me` devuelve `401` sin sesión.

### Inicia un cliente

```bash [Terminal]
npm run dev:web     # http://localhost:3000
```

El proxy de servidor de la app web reenvía `/api/v1/*` a `http://localhost:8787` en desarrollo (`runtimeConfig.apiOrigin`). Crea una cuenta desde la pantalla de registro.
::

## Habilitar las funcionalidades de modelos

Sin `META_API_KEY`, la autenticación, los contactos y los ajustes funcionan, pero enviar un mensaje de chat devuelve `503`. Para generar respuestas, agrega tu clave al archivo ignorado:

```bash [apps/api/.dev.vars]
BETTER_AUTH_URL=http://localhost:8787
BETTER_AUTH_SECRET=<generated by auth:setup:local>
META_API_KEY=<your key>
META_CHAT_MODEL=muse-spark-1.3
AI_GATEWAY_ID=
```

::warning
Nunca hagas commit de `.dev.vars` ni pegues claves en issues, chats o logs. La plantilla `apps/api/.dev.vars.example` contiene solo nombres y comentarios. Consulta [Variables de entorno](/es/getting-started/environment-variables) para ver todos los valores opcionales (ElevenLabs, APNs, Web Push, MCP OAuth).
::

## Panel de administración en local

`wrangler dev` no puede servir por HTTP un entrypoint con nombre como `AdminAPI`. Para uso local, la API puede montar las rutas de administración en su app pública:

```bash [apps/api/.dev.vars]
ADMIN_LOCAL_ROUTES=true
SUPER_ADMIN_USER_IDS=<your local user ID>
```

```bash [Terminal]
npm run dev          # API en http://localhost:8787
npm run dev:admin    # panel en http://localhost:3001
```

Inicia sesión en el panel; la pantalla "Not a super admin" muestra el ID de usuario que debes poner en la lista. **Nunca** definas `ADMIN_LOCAL_ROUTES` en `wrangler.jsonc`.

## Sitio de marketing y documentación

```bash [Terminal]
npm run dev:site     # http://localhost:3002
npm run dev:docs     # http://localhost:3004
```

Ninguno necesita la API. Para revisar la salida de producción de un sitio estático, compílalo y sírvelo con el servidor de assets de Wrangler:

```bash [Terminal]
npm run build:docs
cd apps/docs && npx wrangler dev --config wrangler.jsonc --port 3005
```

## App iOS

```bash [Terminal]
npm run ios    # abre apps/ios/Wildcard.xcodeproj
```

Selecciona el scheme `Wildcard`. Debug y Release apuntan a la API pública mediante el build setting `WILDCARD_API_URL`. Para usar el simulador con tu API local, sobrescribe el valor de Debug con `http://localhost:8787` (y permite las conexiones de red locales en App Transport Security si el sistema operativo lo requiere). Los dispositivos físicos necesitan un origen HTTPS accesible, porque `localhost` apunta al propio dispositivo. Para un dispositivo físico, selecciona tu propio equipo de firma y tus propios bundle identifiers.

## Comandos locales útiles

| Comando | Propósito |
| --- | --- |
| `npm run db:migrate:local` | Aplica solo las migraciones pendientes a la D1 local (por ejemplo, después de hacer pull) |
| `npm run types --workspace @wildcard/api` | Regenera `worker-configuration.d.ts` después de editar `wrangler.jsonc` |
| `npm run typecheck` | Tipos de la API y verificación de TypeScript |
| `npm run typecheck:web` | Tipos de la web con `vue-tsc` |
| `npm run test:lifecycle` | Pruebas de integración del ciclo de vida con D1/R2/Workflows locales en Miniflare |
| `node scripts/check-locales.mjs` | Valida los mensajes en inglés y español de la web y el sitio |

## Limitaciones de la emulación local

- Los **conectores MCP con OAuth** necesitan un `BETTER_AUTH_URL` y un origen web HTTPS públicos, así que no funcionan en `localhost`. Las conexiones MCP públicas y con Bearer sí funcionan.
- **APNs** requiere HTTP/2, que el `workerd` local de macOS puede no soportar.
- La **memoria semántica** (`SEMANTIC_MEMORY_ENABLED=true`) llama al binding remoto de Workers AI incluso en desarrollo local.
- El **AI Gateway** opcional se desactiva en local con `AI_GATEWAY_ID=` (vacío).

::tip
Si la base de datos local queda en mal estado, detén `wrangler dev`, elimina el estado de la D1 local bajo `apps/api/.wrangler/` y vuelve a ejecutar `npm run db:migrate:local`. Los datos de producción nunca se copian en local.
::
