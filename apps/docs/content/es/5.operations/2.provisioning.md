Este es el orden en que debes crear los recursos para que cada binding exista antes de que se publique el código que lo usa. La versión canónica y más detallada es `docs/infrastructure.md`.

## Requisitos previos

- Una cuenta de Cloudflare con Workers, D1, R2 y Workflows disponibles en su plan.
- Un repositorio de GitHub con este código, conectado a Cloudflare mediante la integración de GitHub de Workers Builds.
- Node.js 24+ y un login de Wrangler con lectura de la cuenta, edición de D1 y edición de R2 (solo para el aprovisionamiento).
- Una clave de la Meta Model API con acceso a Muse Spark 1.3 y Muse Voice Transcribe.
- Opcional: clave de ElevenLabs, cuenta de Apple Developer (APNs, App Groups, Associated Domains), claves VAPID.

## Pasos

::steps{level="3"}

### Reemplaza los valores específicos de la cuenta

En `apps/api/wrangler.jsonc`: `account_id`, el `name` del Worker, `vars.BETTER_AUTH_URL`, `vars.MCP_WEB_ORIGIN`, `vars.SUPER_ADMIN_USER_IDS` (empieza vacío), los `name` de los Workflows y el `bucket_name` de R2. Define el `database_name` de D1 y su `database_id` como `00000000-0000-0000-0000-000000000000`. Conserva cada `binding` y `class_name`. Reemplaza `account_id` en los archivos de Wrangler de web, admin, sitio y docs, y los nombres de los servicios si tu Worker de la API tiene otro nombre.

### Crea la base de datos D1

```bash [Terminal]
npm run infra:provision
```

Lista las bases de datos, reutiliza una con el nombre coincidente o crea una, verifica el ID y lo escribe en el binding. Se niega a reemplazar un ID distinto que no sea el placeholder y nunca migra ni despliega.

### Crea el bucket de R2

```bash [Terminal]
npm run infra:photos -- --create
npm run infra:photos
```

Mantén desactivados `r2.dev` y los dominios personalizados públicos.

### Commitea y haz push de la configuración

Revisa la cuenta y los IDs, y luego haz commit y push.

### Conecta el proyecto de Workers Builds de la API

Repositorio y rama `main`, raíz `/`, build `npm ci && npm run typecheck`, deploy `npm run release:ci`, previews desactivadas. Credencial: edición de Workers Scripts, edición de D1, edición de Workflows, acceso a buckets de R2 y lectura de la cuenta. Agrega el secreto de build cifrado `META_API_KEY` (y los opcionales `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*`). Haz push de un commit: el release migra D1, genera `BETTER_AUTH_SECRET`, sube los secretos y publica la API con sus Workflows y su Cron.

### Conecta el proyecto web

Raíz `/`, build `npm ci && npm run typecheck:web && npm run build:web`, deploy `npm run release:web`. Credencial: edición de Workers Scripts y lectura de la cuenta. Para las Previews por rama, habilita los builds que no son de producción con el comando de preview `npm run preview:web`.

### Opcional: admin, sitio y docs

Crea un proyecto para cada uno con los comandos de [Workers Builds](/es/cloudflare/workers-builds#proyectos). Luego inicia sesión en el origen de admin, agrega tu ID de usuario a `SUPER_ADMIN_USER_IDS` y haz push. Define las URLs del sitio en `apps/site/app/utils/site.ts` y la URL de la documentación en `apps/docs/nuxt.config.ts`.

### Opcional: AI Gateway

`npm run infra:ai-gateway -- --create`; luego define `AI_GATEWAY_ID` y haz push una vez verificado.

### Configura los watch paths

Copia las rutas de inclusión de `docs/workers-build-paths.json` en **Settings → Builds** de cada proyecto y elimina el `*` predeterminado.

### Configura la app de iOS

Equipo de firma, bundle IDs, `WILDCARD_API_URL`, `WILDCARD_APP_GROUP`, `WILDCARD_LINK_HOST`, capacidades y clave de APNs (consulta [App de iOS](/es/apps/ios#configuración-para-tu-propia-cuenta)).
::

## Staging

No existe un entorno de staging. Una configuración de staging necesita sus propios nombres de Worker, base de datos D1, bucket de R2, nombres de Workflow, secretos, orígenes y configuración de iOS. Nunca apuntes las Previews ni staging a la base de datos de producción sin querer (las Previews web usan actualmente la API de producción por diseño).
