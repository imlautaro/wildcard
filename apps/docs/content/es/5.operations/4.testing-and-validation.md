## Verificaciones de tipos

| Comando | Qué comprueba |
| --- | --- |
| `npm run typecheck` | Regenera los tipos de los bindings del Worker y ejecuta TypeScript 7 sobre la API |
| `npm run typecheck:web` / `:admin` / `:site` | `nuxt prepare` más `vue-tsc` sobre un compilador TypeScript 6 con alias |
| `npm run typecheck:docs` | `nuxt prepare` para el sitio de documentación |
| `npm run typecheck:lifecycle` | Tipos del fixture de los tests de ciclo de vida |

Workers Builds ejecuta la verificación de tipos antes de cada build, así que un error de tipos bloquea el release.

## Tests de integración del ciclo de vida

```bash [Terminal]
npm run test:lifecycle
npm run test:memory-isolation --workspace @wildcard/api   # solo los tests isolation:
```

`apps/api/tests/lifecycle.test.mjs` (el test runner de Node) empaqueta `tests/lifecycle.worker.ts` con esbuild y lo ejecuta en **Miniflare** con D1 y R2 locales y Workflows simulados, aplicando todas las migraciones en orden. Las llamadas de red salientes devuelven `503`, así que no se llama a ningún proveedor real. La suite cubre el vaciado de chats y grupos, el outbox de limpieza con fallos inyectados de R2 y de Workflows, reintentos, backoff y condiciones de carrera, reparaciones de migraciones, la eliminación de cuentas, contactos y administradores, y el aislamiento de memoria y el consentimiento.

## Comprobaciones estáticas

- `scripts/checks/*-sql-compile.*` compilan las sentencias SQL de varias funciones contra SQLite.
- `scripts/checks/*.cjs` ejercitan lógica pura como la energía de grupo, las confirmaciones y la publicación.
- `node scripts/check-locales.mjs` valida los mensajes en inglés y español de la web y del sitio: paridad de claves, compilación ICU, placeholders y ramas de plural, y que cada clave usada en el código exista.
- El proyecto de iOS se puede verificar estáticamente con `swiftc -typecheck` usando los flags de aislamiento del proyecto.

## Evaluaciones en vivo

`scripts/checks/conversation-style-live-eval.mjs`, `personality-live-eval.mjs` y `mini-app-eval.mjs` llaman a la API real de Meta (leyendo `META_API_KEY` de `.dev.vars`) con datos ficticios. Consumen créditos y solo se ejecutan cuando se piden explícitamente.

## Política

- Los acuerdos de trabajo permiten la validación estática en cualquier momento; los builds y los tests se ejecutan cuando se piden.
- Nunca uses datos reales de cuentas para validar una función. Nunca afirmes un comportamiento en dispositivos a partir de comprobaciones estáticas: cada guía enumera lo que queda por verificar en dispositivos.
