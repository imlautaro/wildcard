Este sitio es el workspace `@wildcard/docs` en `apps/docs`, construido con [Docus](https://docus.dev) 5 (una capa de Nuxt sobre Nuxt Content, Nuxt UI y Tailwind CSS 4).

## Estructura

```text
apps/docs/
├── app/
│   ├── app.config.ts     # Encabezado, colores, navegación, valores SEO predeterminados
│   └── app.css           # Escala de colores de la marca Wildcard y Manrope
├── content/
│   ├── en/               # Páginas en inglés
│   └── es/               # Páginas en español (árbol idéntico)
├── public/               # favicon, fuentes, _redirects
├── nuxt.config.ts        # extiende docus, i18n (en, es), preset static
├── wrangler.jsonc        # Worker solo de assets wildcard-docs
└── package.json
```

Las carpetas de primer nivel en `content/<locale>/` se convierten en las pestañas del encabezado; los prefijos numéricos (`1.getting-started`) definen el orden y `.navigation.yml` define el título y el ícono de cada sección.

## Edición

```bash [Terminal]
npm run dev:docs    # http://localhost:3004
```

- Escribe Markdown con componentes MDC (`::note`, `::steps`, `::card-group`, `::accordion`, bloques de código con nombres de archivo).
- **Cada página existe tanto en `content/en` como en `content/es`** con la misma ruta. El español usa el "tú" latinoamericano neutro y los mismos términos de producto que las apps.
- Los datos salen del código y de `docs/`. Cuando no coinciden, gana el código; corrige también la guía.
- Nunca incluyas valores de secretos. Los identificadores de recursos de la guía
  de infraestructura son ejemplos que debes reemplazar para otra instalación.

## Guías de referencia completas

La pestaña [Referencia](/es/reference) publica todas las guías Markdown de `docs/`,
incluidas las de [chats privados](/es/reference/chats) y
[grupos](/es/reference/groups), como páginas completas dentro de este sitio.
El inglés sale directamente de las guías mantenidas; las traducciones completas
al español están en `apps/docs/reference/es/`. Los resúmenes enlazan a esas guías
y los enlaces entre guías permanecen en el idioma elegido. Los enlaces a secciones
conservan anclas estables en inglés en ambos idiomas.

`node scripts/prepare-docs-reference.mjs` se ejecuta automáticamente antes de dev,
la comprobación de tipos y los builds de Docs. Comprueba las revisiones SHA-256
del original en `apps/docs/reference/es/sources.json` y rechaza traducciones
faltantes o desactualizadas. Al cambiar una guía, actualiza su traducción completa
y su revisión juntas. No edites ni incluyas en commits los directorios generados
`content/*/6.reference/` ni `public/reference-assets/`; reinicia dev después de
cambiar los originales para regenerarlos.

Ejecuta `node scripts/check-docs-reference.mjs` después de preparar el contenido
para comprobar cobertura, análisis de Markdown, enlaces internos y anclas de
secciones sin hacer un build. La verificación en navegador de las nuevas páginas
de referencia completas sigue pendiente.

La configuración de filtros se puede leer dentro del sitio en
[Filtros de builds](/es/reference/workers-build-paths). Las imágenes Open Graph
tienen un límite de renderizado de 60 segundos para el arranque en frío de CI;
los errores de páginas o imágenes siguen haciendo fallar el build.

## Build y publicación

```bash [Terminal]
npm run build:docs   # nuxt generate → apps/docs/.output/public
```

- `nitro.preset: 'static'` prerrenderiza cada página, `/llms.txt`, `/llms-full.txt`, el Markdown en bruto bajo `/raw/…`, los sitemaps y las imágenes de Open Graph. La búsqueda se ejecuta en el navegador.
- `prerender.failOnError` más el rastreo de enlaces hacen que los enlaces internos rotos hagan fallar el build.
- El Worker `wildcard-docs` sirve `.output/public` como assets estáticos con `not_found_handling: "404-page"`. `public/_redirects` envía `/` a `/en`.
- Las funciones de servidor de Docus (asistente de IA, servidor MCP) necesitan un runtime de servidor y no están disponibles en este despliegue estático.

## Release

Workers Builds se conectó el 2 de noviembre de 2026. Los releases de producción
se ejecutan automáticamente después de hacer push a `main` en el repositorio
conectado. La raíz del build es `/`, el comando de build es
`npm ci && npm run typecheck:docs && npm run build:docs` y el comando de deploy es
`npm run release:docs`. Los builds de preview están desactivados y la caché de
build está activada.

Los watch paths requeridos son `apps/docs/*`, `docs/*`,
`scripts/prepare-docs-reference.mjs`, `scripts/release-docs.mjs`, `package.json`,
`package-lock.json`, `.nvmrc`, `.npmrc` y `.gitignore`, sin exclusiones.
Los inputs de referencia (`docs/*` y el script de preparación) se añadieron al
dashboard de producción de Cloudflare Builds el 2 de noviembre de 2026. Este sitio extiende Docus, por lo que no observa `packages/ui/*`. Un cambio limitado
al contenido de este sitio reconstruye Docs sin reconstruir la API, la web, el
panel de administración ni el sitio de marketing. Los cambios en las dependencias
de la raíz pueden afectar a todos los proyectos.

`scripts/release-docs.mjs` exige Workers Builds, la rama de producción, un checkout
limpio y que HEAD coincida con el SHA enviado; etiqueta la versión publicada con
ese SHA. Verifica el build exitoso y la versión de origen activa después de cada
release. Nunca publiques manualmente.
