## Desarrollo local

::accordion
  :::accordion-item{label="Enviar un mensaje devuelve 503" icon="i-lucide-circle-alert"}
  Falta `META_API_KEY` en `apps/api/.dev.vars`. La autenticación y los contactos funcionan sin ella; las respuestas la necesitan. Reinicia `wrangler dev` después de editar `.dev.vars`.
  :::

  :::accordion-item{label="La autenticación falla con un error de secreto" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` falta o tiene menos de 32 caracteres. Ejecuta `npm run auth:setup:local` (no sobrescribe un archivo existente; elimina primero uno defectuoso).
  :::

  :::accordion-item{label="Errores de SQL por tablas o columnas inexistentes" icon="i-lucide-circle-alert"}
  Tu D1 local está desactualizado. Ejecuta `npm run db:migrate:local`.
  :::

  :::accordion-item{label="El panel de administración muestra 404 o 'Not a super admin'" icon="i-lucide-circle-alert"}
  Define `ADMIN_LOCAL_ROUTES=true` y tu ID de usuario local en `SUPER_ADMIN_USER_IDS` en `.dev.vars`, y luego reinicia la API.
  :::

  :::accordion-item{label="Los tipos están desactualizados después de editar wrangler.jsonc" icon="i-lucide-circle-alert"}
  Ejecuta `npm run types --workspace @wildcard/api` (o `npm run typecheck`, que lo incluye).
  :::

  :::accordion-item{label="vue-tsc no logra cargar TypeScript" icon="i-lucide-circle-alert"}
  Las apps Nuxt verifican los tipos con el paquete con alias `typescript6` a través de su `scripts/typecheck.mjs`. Ejecuta el script de npm en lugar de llamar a `vue-tsc` directamente.
  :::

  :::accordion-item{label="MCP OAuth no funciona localmente" icon="i-lucide-circle-alert"}
  OAuth requiere orígenes HTTPS públicos para la API y la app web. Usa conexiones públicas o Bearer localmente.
  :::

  :::accordion-item{label="La app web falla al iniciar después de agregar un composable" icon="i-lucide-circle-alert"}
  Busca un ciclo de importaciones a través de `useSession`. No debe importar otros composables.
  :::
::

## Producción

::accordion
  :::accordion-item{label="Un release de Workers Builds se niega a ejecutarse" icon="i-lucide-circle-alert"}
  Lee el mensaje de la protección: debe ejecutarse en Workers Builds, en la rama de producción, con un checkout limpio y `HEAD` igual a `WORKERS_CI_COMMIT_SHA`. El primer build después de conectar un repositorio puede no tener metadatos; haz push de otro commit. No te saltes la protección con un deploy manual.
  :::

  :::accordion-item{label="El release de la API se detiene por META_API_KEY" icon="i-lucide-circle-alert"}
  El secreto de build está vacío, o falta tanto en el build como en runtime. Define la variable de build cifrada y vuelve a hacer push.
  :::

  :::accordion-item{label="El build de admin falla después de un cambio en la API" icon="i-lucide-circle-alert"}
  Puede que el binding de admin haga referencia a un cambio de `AdminAPI` que la API todavía no publicó. Reintenta el build de admin después de que `wildcard-api` termine con éxito.
  :::

  :::accordion-item{label="Las respuestas fallan con HTTP 502 a través del AI Gateway" icon="i-lucide-circle-alert"}
  Esto ocurrió el 27 de octubre de 2026. Vacía `AI_GATEWAY_ID` (llamadas directas) y haz push; investiga el gateway por separado.
  :::

  :::accordion-item{label="Se cerró la sesión de todos" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` cambió (por una rotación, o porque el Worker se eliminó y se volvió a crear). Las sesiones y las credenciales MCP cifradas con el secreto anterior ya no son válidas.
  :::

  :::accordion-item{label="No llegan notificaciones push" icon="i-lucide-circle-alert"}
  Comprueba que los cuatro secretos de build `APNS_*` (o los tres `VAPID_*`) estén definidos y publicados, que `APNS_TOPIC` coincida con el bundle ID y que el `APNS_ENVIRONMENT` de la app coincida con la firma. Busca los eventos `push_accepted`, `push_provider_signing_failed` o `push_delivery_deferred` en Workers Logs.
  :::

  :::accordion-item{label="Un turno quedó atascado en Escribiendo" icon="i-lucide-circle-alert"}
  `recoverChats` del Cron de cada minuto concilia los turnos con el estado de su Workflow. Revisa la instancia del Workflow en el dashboard (`chat-<turnID>-a1`) y los errores del modelo en Workers Logs.
  :::
::

## Dónde buscar

- **Workers Logs y trazas** en el dashboard de Cloudflare de cada Worker (solo eventos sanitizados).
- El dashboard de **Workflows** para el estado de las instancias y el historial de pasos.
- Los logs de **Workers Builds** para la salida del build y del release.
- La guía de la función en `docs/` para las limitaciones conocidas y la verificación pendiente.
