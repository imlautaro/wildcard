## Escribir una migración

1. Crea el siguiente archivo en `apps/api/migrations`, por ejemplo `0094_my_feature.sql`. Los números son secuenciales y los nombres describen el cambio.
2. Escribe SQLite plano. Prefiere cambios **aditivos**: tablas nuevas, columnas nuevas que admitan nulos o tengan valor predeterminado, índices y triggers nuevos.
3. Mantenla compatible con la versión del Worker que está activa: la migración se ejecuta **antes** de que se suba el código nuevo, y el código anterior debe seguir funcionando con el esquema nuevo durante el release y después de un rollback del código.
4. Nunca edites una migración que ya se haya aplicado en algún lugar.

```sql [apps/api/migrations/0094_example.sql]
-- Aditiva: el código anterior ignora la columna nueva.
ALTER TABLE contact ADD COLUMN example_flag INTEGER NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS contact_example_idx ON contact(user_id, example_flag);
```

## Validar localmente

```bash [Terminal]
npm run db:migrate:local            # aplica las migraciones pendientes al D1 local
npm run test:lifecycle              # tests de regresión de limpieza, eliminación y aislamiento
```

- D1 limita las sentencias `SELECT` compuestas a cinco términos; comprueba el SQL poco habitual contra el D1 local de `workerd`.
- Los scripts `scripts/checks/*-sql-compile.*` compilan de forma estática el SQL que usan varias funciones.
- Si una migración agrega filas que deben eliminarse junto con su propietario, extiende los triggers de `resource_cleanup` y los tests de ciclo de vida.

## Publicar

Haz commit y push. El release de la API aplica las migraciones pendientes con `wrangler d1 migrations apply DB --remote` y solo después despliega el código. `npm run db:migrate:remote` existe únicamente para operaciones autorizadas de forma explícita.

## Documentar

Toda migración que agregue un servicio, permiso o comportamiento debe describirse en [`docs/infrastructure.md`](/es/reference/infrastructure) (configuración, verificación, rollback y compatibilidad de datos) y en la guía de la función. Las guías hacen referencia a las migraciones por número (por ejemplo, "migración 0093").
