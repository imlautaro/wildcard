## Desarrollo local

::accordion
  :::accordion-item{label="Enviar un mensaje devuelve 503" icon="i-lucide-circle-alert"}
  Falta `META_API_KEY` en `apps/api/.dev.vars`. La autenticación y los contactos funcionan sin ella; las respuestas la necesitan. Reinicia `npm run dev` después de editar `.dev.vars`.
  :::

  :::accordion-item{label="El puerto 8787 o 3000 ya está en uso" icon="i-lucide-circle-alert"}
  `npm run dev` y `npm run dev:all` se detienen en lugar de pasar a otro puerto, porque si no el proxy web, `BETTER_AUTH_URL` y el cron local se comunicarían con lo que ocupe ese puerto. Detén el otro proceso (a menudo otro checkout de Wildcard) o elige otros puertos con `API_PORT` / `WEB_PORT` en el entorno o en el `.env` de la raíz, por ejemplo `API_PORT=8797 npm run dev:all`.
  :::

  :::accordion-item{label="Los datos locales desaparecieron después de hacer pull" icon="i-lucide-circle-alert"}
  El ID versionado de la D1 local cambió a un placeholder, así que Wrangler abrió una base de datos local nueva y vacía. Ejecuta `npm run setup` una vez para aplicarle las migraciones.
  :::

  :::accordion-item{label="wrangler dev pide iniciar sesión en Cloudflare" icon="i-lucide-circle-alert"}
  Inicia la API con `npm run dev` (o `npm run dev:all`), no con un `wrangler dev` directo: el script omite el binding de Workers AI, que siempre es remoto, así que no hace falta iniciar sesión.
  :::

  :::accordion-item{label="La autenticación falla con un error de secreto" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` falta o tiene menos de 32 caracteres. Ejecuta `npm run setup` (nunca sobrescribe valores existentes; elimina primero un archivo defectuoso).
  :::

  :::accordion-item{label="Errores de SQL por tablas o columnas inexistentes" icon="i-lucide-circle-alert"}
  Tu D1 local está desactualizado. Ejecuta `npm run db:migrate:local`.
  :::

  :::accordion-item{label="El panel de administración muestra 404 o 'Not a super admin'" icon="i-lucide-circle-alert"}
  Define `ADMIN_LOCAL_ROUTES=true` y tu ID de usuario local en `SUPER_ADMIN_USER_IDS` en `.dev.vars`, y luego reinicia la API.
  :::

  :::accordion-item{label="Los tipos están desactualizados después de editar wrangler.jsonc" icon="i-lucide-circle-alert"}
  Ejecuta `npm run types --workspace @wildcard/api` (o `npm run typecheck`, que lo incluye).
  :::

  :::accordion-item{label="vue-tsc no logra cargar TypeScript" icon="i-lucide-circle-alert"}
  Las apps Nuxt verifican los tipos con el paquete con alias `typescript6` a través de su `scripts/typecheck.mjs`. Ejecuta el script de npm en lugar de llamar a `vue-tsc` directamente.
  :::

  :::accordion-item{label="MCP OAuth no funciona localmente" icon="i-lucide-circle-alert"}
  OAuth requiere orígenes HTTPS públicos para la API y la app web. Usa conexiones públicas o Bearer localmente.
  :::

  :::accordion-item{label="La app web falla al iniciar después de agregar un composable" icon="i-lucide-circle-alert"}
  Busca un ciclo de importaciones a través de `useSession`. No debe importar otros composables.
  :::
::

## Producción

::accordion
  :::accordion-item{label="Un release se niega a ejecutarse" icon="i-lucide-circle-alert"}
  Lee el mensaje de la protección: debe ejecutarse en Workers Builds o en el workflow de deploy de GitHub Actions, en la rama de producción, con un checkout limpio y `HEAD` igual al commit que lo disparó (`WORKERS_CI_COMMIT_SHA` o `GITHUB_SHA`). El primer build después de conectar un repositorio puede no tener metadatos; haz push de otro commit. No te saltes la protección con un deploy manual. `npm run release:check` enumera los problemas sin hacer el release.
  :::

  :::accordion-item{label="El workflow Deploy de GitHub Actions se omite" icon="i-lucide-circle-alert"}
  El job solo se ejecuta cuando la variable del repositorio `WILDCARD_DEPLOY` es exactamente `true`. Defínela en **Settings → Secrets and variables → Actions → Variables**.
  :::

  :::accordion-item{label="Las respuestas tardan justo después del primer release" icon="i-lucide-circle-alert"}
  Un Cron Trigger y unos Workflows recién creados pueden tardar varios minutos (Cloudflare documenta hasta 15) en activarse. Los mensajes enviados en ese intervalo pueden quedar en cola hasta que la primera ejecución del Cron los recupere; no se pierde nada. Espera unos 15 minutos después del primer release antes de ejecutar `npm run smoke`, o vuelve a ejecutarlo si en ese momento se agota el tiempo. Los releases posteriores no se ven afectados.
  :::

  :::accordion-item{label="La credencial puede acceder a varias cuentas" icon="i-lucide-circle-alert"}
  El release no puede elegir una cuenta por sí solo. Define `CLOUDFLARE_ACCOUNT_ID` como variable de GitHub Actions o variable de build de Workers Builds (en local, expórtala antes de `npm run release:check`), o limita el token a una sola cuenta.
  :::

  :::accordion-item{label="La cuenta no tiene subdominio workers.dev" icon="i-lucide-circle-alert"}
  Los orígenes predeterminados son `https://<worker>.<subdomain>.workers.dev`. Abre **Workers & Pages** una vez en el dashboard de Cloudflare para crear el subdominio, o define tanto `WILDCARD_API_URL` como `WILDCARD_WEB_URL` con tus propios orígenes `https://`, y vuelve a hacer el release.
  :::

  :::accordion-item{label="El release de la API se detiene por META_API_KEY" icon="i-lucide-circle-alert"}
  El secreto de CI está vacío, o falta tanto en CI como en runtime. Define la variable de build cifrada de Workers Builds (o el secreto de GitHub Actions) y vuelve a hacer push.
  :::

  :::accordion-item{label="El release de la API pide configurar juntos los secretos de APNs o VAPID" icon="i-lucide-circle-alert"}
  Solo está definida una parte del grupo `APNS_*` (cuatro) o `VAPID_*` (tres). Define todos o ninguno; los valores vacíos cuentan como no definidos.
  :::

  :::accordion-item{label="El build de admin falla después de un cambio en la API" icon="i-lucide-circle-alert"}
  Puede que el binding de admin haga referencia a un cambio de `AdminAPI` que la API todavía no publicó. Reintenta el build de admin después de que `wildcard-api` termine con éxito.
  :::

  :::accordion-item{label="Las respuestas fallan con HTTP 502 a través del AI Gateway" icon="i-lucide-circle-alert"}
  Esto ocurrió el 27 de octubre de 2026. Vacía `AI_GATEWAY_ID` (llamadas directas) y haz push; investiga el gateway por separado.
  :::

  :::accordion-item{label="Se cerró la sesión de todos" icon="i-lucide-circle-alert"}
  `BETTER_AUTH_SECRET` cambió (por una rotación, o porque el Worker se eliminó y se volvió a crear). Las sesiones y las credenciales MCP cifradas con el secreto anterior ya no son válidas.
  :::

  :::accordion-item{label="No llegan notificaciones push" icon="i-lucide-circle-alert"}
  Comprueba que los cuatro secretos de build `APNS_*` (o los tres `VAPID_*`) estén definidos y publicados, que `APNS_TOPIC` coincida con el bundle ID y que el `APNS_ENVIRONMENT` de la app coincida con la firma. Busca los eventos `push_accepted`, `push_provider_signing_failed` o `push_delivery_deferred` en Workers Logs.
  :::

  :::accordion-item{label="Un turno quedó atascado en Escribiendo" icon="i-lucide-circle-alert"}
  `recoverChats` del Cron de cada minuto concilia los turnos con el estado de su Workflow. Revisa la instancia del Workflow en el dashboard (`chat-<turnID>-a1`) y los errores del modelo en Workers Logs.
  :::
::

## Dónde buscar

- **Workers Logs y trazas** en el dashboard de Cloudflare de cada Worker (solo eventos sanitizados).
- El dashboard de **Workflows** para el estado de las instancias y el historial de pasos.
- Los logs de **Workers Builds** para la salida del build y del release.
- La guía de la función en `docs/` para las limitaciones conocidas y la verificación pendiente.
