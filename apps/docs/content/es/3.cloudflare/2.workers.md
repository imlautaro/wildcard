## Los cinco Workers

| Worker | Configuración | Tipo | Bindings |
| --- | --- | --- | --- |
| `wildcard-api` | `apps/api/wrangler.jsonc` | Script (`src/index.ts`) | `DB`, `CONTACT_PHOTOS`, `CHAT_WORKFLOW`, `ONBOARDING_WORKFLOW`, `AI`, Cron |
| `wildcard-web` | `apps/web/wrangler.jsonc` → `.output/server/wrangler.json` | Nitro `cloudflare_module` | `API` (service), `ASSETS` |
| `wildcard-admin` | `apps/admin/wrangler.jsonc` → `.output/server/wrangler.json` | Nitro `cloudflare_module` | `API` (service, entrypoint `AdminAPI`), `ASSETS` |
| `wildcard-site` | `apps/site/wrangler.jsonc` | Solo assets estáticos | ninguno |
| `wildcard-docs` | `apps/docs/wrangler.jsonc` | Solo assets estáticos | ninguno |

Todos los Workers usan `compatibility_date: "2026-10-26"`. Los Workers con script activan `nodejs_compat`; la API también activa `global_fetch_strictly_public`, así que `fetch` desde la API solo puede llegar a direcciones públicas (importante para las vistas previas de enlaces, los monitores de páginas y el tráfico de salida de MCP).

## Puntos de entrada de la API

`apps/api/src/index.ts` exporta:

```ts [apps/api/src/index.ts (simplified)]
export { OnboardingWorkflow } from './onboarding/workflow';
export { ChatWorkflow } from './chat/workflow';

// Accesible solo a través de un service binding con el entrypoint "AdminAPI".
export class AdminAPI extends WorkerEntrypoint<Env> {
  fetch(request: Request) { return adminApp.fetch(request, this.env, this.ctx); }
}

export default {
  fetch: app.fetch,            // app Hono pública: /api/v1/*
  scheduled(event, env, ctx) { /* tareas del Cron de cada minuto, cada una en ctx.waitUntil */ },
};
```

## Service bindings

Los Workers web y de administración nunca llaman a la API por internet público. Su ruta de servidor de Nitro `server/api/v1/[...path].ts`:

1. Rechaza segmentos de punto y separadores codificados (`404`) y las solicitudes cross-site que no sean GET (`403`, verificado con `Sec-Fetch-Site` y `Origin`).
2. Reconstruye la solicitud hacia la API a partir de una lista permitida de encabezados: `Accept`, `Content-Type`, `Authorization: Bearer <token from the cookie>` y `CF-Connecting-IP` (para que los rate limits por IP sigan aplicándose en la API).
3. Llama a `env.API.fetch(new Request('https://wildcard-api.internal' + path, …))`.
4. Devuelve solo los encabezados de respuesta permitidos y agrega `Cache-Control: no-store`.
5. En el inicio de sesión o el registro, guarda el encabezado `set-auth-token` en una cookie `httpOnly` y devuelve solo `{ user }`.

| Cookie | Worker | Atributos |
| --- | --- | --- |
| `__Host-wildcard_session` | Web | `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, 7 días |
| `__Host-wildcard_admin_session` | Admin | Los mismos atributos |

En desarrollo, los nombres de las cookies no llevan el prefijo `__Host-` y el proxy llama a `http://localhost:8787` con un `fetch` normal.

### El entrypoint `AdminAPI`

El binding de administración apunta a `entrypoint: "AdminAPI"`. En el origen público de la API, `/api/v1/admin/*` devuelve `404`; solo el Worker de administración puede llegar a las rutas de administración. Además, el proxy de administración solo reenvía `POST /api/v1/auth/sign-in/email`, `POST /api/v1/auth/sign-out` y `/api/v1/admin/*`.

## Assets estáticos

- **Web y admin**: Nitro agrega un binding `ASSETS` y escribe `.output/server/wrangler.json` con `main` y `assets`. Los releases despliegan ese archivo generado, nunca directamente el `wrangler.jsonc` de origen.
- **Site y docs**: Workers solo de assets sirven `.output/public` con `html_handling: "auto-trailing-slash"` y `not_found_handling: "404-page"`. La documentación también incluye un archivo `_redirects` que envía `/` a `/en`.

## Encabezados de seguridad

La aplicación web define, en todas las rutas: `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY` y `Permissions-Policy: camera=(), microphone=(self), geolocation=()`. El panel de administración también envía `X-Robots-Tag` (noindex) y desactiva el micrófono. Todas las respuestas de la API llevan `Cache-Control: no-store`.

## Observabilidad

| Worker | Logs | Trazas | Query strings |
| --- | --- | --- | --- |
| API | Activados, muestreo inicial 1 | Activadas, muestreo inicial 0.01 | Ocultadas |
| Web, admin | Activados, muestreo inicial 1 | — | Ocultadas |

La API registra nombres de eventos saneados (por ejemplo `push_accepted`, `push_delivery_deferred`) y nunca contenido de conversaciones, tokens ni secretos.

## Orígenes y Previews

- Todos los Workers tienen `workers_dev: true`. La instalación de referencia sirve `https://<worker>.imlautaro.workers.dev`; un fork obtiene el subdominio de su propia cuenta, que el release de la API usa para los orígenes predeterminados.
- `preview_urls` está activado para la API, web y admin, pero **solo el proyecto web compila Previews de ramas**. El `wrangler.jsonc` de web tiene un bloque `previews` que repite el binding `API`; por lo tanto, una Preview se comunica con la API y los datos de **producción**.
- La API y admin no tienen bloque `previews`: una Preview de la API arrancaría sin sus secretos y requeriría decisiones sobre D1 y Workflows.
