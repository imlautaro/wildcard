El panel de administración (`@wildcard/admin`, Worker `wildcard-admin`) es una SPA opcional de Nuxt 4 en inglés. Comparte la capa de UI con la aplicación web. Guía de funciones: `docs/admin.md`.

## Qué pueden hacer los super administradores

- Abrir o cerrar el **registro** (`registration_enabled`).
- Activar los **mensajes de voz de los contactos** (`voice_messages_enabled`).
- Forzar **Contributor en todas las cuentas** (`contributor_only`) durante las pruebas; la elección de modelo guardada vuelve al desactivarlo.
- Listar cuentas con su cantidad de contactos y **eliminar una cuenta** con todos sus datos. La eliminación es duradera: los objetos de R2 y las instancias de Workflow se eliminan de forma asíncrona mediante el outbox de limpieza (migración 0069).
- Inspeccionar vistas de laboratorio, como las miniapps.

Páginas: `/`, `/sign-in`, `/users`, `/settings`, `/mini-apps`. Los cambios se registran en `admin_event`.

## Modelo de acceso

```text
Browser ──cookie──▶ wildcard-admin ──service binding (entrypoint AdminAPI)──▶ wildcard-api
```

- El binding apunta al entrypoint con nombre `AdminAPI`, un `WorkerEntrypoint` que sirve la app Hono de administración. **No es accesible desde el origen público de la API**: `GET /api/v1/admin/session` en el origen de la API devuelve `404`.
- El proxy de administración solo reenvía el inicio de sesión, el cierre de sesión y `/api/v1/admin/*`; `/api/v1/me` devuelve `404` en el origen de administración.
- La autorización es una lista: `SUPER_ADMIN_USER_IDS` (IDs de usuario separados por comas, una variable simple del Worker que el release define desde la variable de CI `WILDCARD_SUPER_ADMIN_USER_IDS`; vacía en `apps/api/wrangler.jsonc`). Cualquier otra persona recibe `403 NOT_SUPER_ADMIN`.
- Cookie de sesión: `__Host-wildcard_admin_session` (`HttpOnly`, `Secure`, `SameSite=Strict`).

::tip
Para tener protección adicional, puedes poner Cloudflare Access delante de `wildcard-admin`. No está configurado en este repositorio.
::

## Agregar un super administrador

1. Inicia sesión en el origen de administración. La pantalla "Not a super admin" muestra tu ID de usuario.
2. Agrégalo a `WILDCARD_SUPER_ADMIN_USER_IDS` (separado por comas): una variable del repositorio en GitHub Actions o una variable de build del proyecto de Workers Builds de la API.
3. Vuelve a publicar la API (haz push de un commit, reintenta el último build de la API o ejecuta el workflow **Deploy** de GitHub Actions); el release aplica el cambio.

Para revocar el acceso, quita el ID y haz el release de la API. Cada release de la API aplica el valor actual, así que vaciar o eliminar la variable revoca todo el acceso de administración. El panel en sí no guarda datos.

## Desarrollo local

Consulta [Desarrollo local → Panel de administración en local](/es/getting-started/local-development#panel-de-administración-en-local): `wrangler dev` no puede servir entrypoints con nombre, así que `ADMIN_LOCAL_ROUTES=true` en `.dev.vars` monta las rutas de administración en la app pública local.

## Orden de los releases

Si el build de administración se ejecuta antes del release de la API que exporta un cambio nuevo de `AdminAPI`, el binding puede apuntar a código que todavía no existe. Vuelve a ejecutar el build de administración después de que `wildcard-api` termine correctamente.
