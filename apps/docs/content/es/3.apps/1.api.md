La API (`@wildcard/api`, Worker `wildcard-api`) es una aplicación Hono que es dueña de todos los datos y de toda la lógica. Los clientes solo se comunican con ella.

## Estructura del código

| Ruta | Responsabilidad |
| --- | --- |
| `src/index.ts` | Entrada del Worker: `fetch` público, Cron `scheduled`, clases de Workflow, entrypoint `AdminAPI` |
| `src/app.ts` | App Hono pública: middleware, montaje de rutas, handlers de 404 y de errores |
| `src/lib/` | Autenticación (`auth.ts`, `auth-routes.ts`, `session.ts`), rate limits, preferencia de modelo, runtime de esquemas, conteos de no leídos |
| `src/routes/` | `me`, `contacts`, `chats`, `push`, `schedules`, `sharing`, `debug-export` |
| `src/chat/` | Motor de chats privados: despacho, `ChatWorkflow`, cliente de Meta (`meta.ts`), contexto y herramientas (`context.ts`), presencia, ritmo, memoria, memoria semántica, iniciativa, aprendizaje, adjuntos, transcripción, limpieza, exportación |
| `src/groups/` | Rutas de grupos, rondas de respuestas y planificación, energía, membresía, solicitudes, confirmaciones, archivos multimedia, push |
| `src/contacts/` | Generación de contactos con IA, retratos, nombres, alias, contactos vinculados |
| `src/personality/` | Perfil de personalidad, motor, relaciones, director de actuación, estilo de conversación |
| `src/onboarding/` | Rutas de onboarding y `OnboardingWorkflow` |
| `src/home/` | Para ti: curador, tarjetas, comentarios, workflow |
| `src/tasks/`, `src/documents/`, `src/research/`, `src/monitors/`, `src/schedules/` | Funciones de trabajo agéntico |
| `src/miniapps/` | Especificaciones declarativas de miniapps, verificación y estado |
| `src/mcp/` | Cliente MCP, OAuth, presets, control de acceso, guarda de SSRF/DNS, validación de esquemas |
| `src/native/` | Acciones nativas de iOS y ejecución remota en el dispositivo |
| `src/photos/`, `src/stickers/`, `src/voice/`, `src/links/` | Multimedia: generación de imágenes, fotos firmadas para push, stickers, voces, vistas previas de enlaces |
| `src/push/` | APNs (`delivery.ts`) y Web Push (`web.ts`) |
| `src/reactions/`, `src/replies/` | Reacciones y respuestas con cita |
| `src/admin/` | App Hono de administración, rutas y configuración de runtime |
| `src/db/schema.ts` | Tablas de Drizzle que usa el adaptador de Better Auth |

## Superficie HTTP

Todas las rutas están bajo `/api/v1`. Cada respuesta lleva `Cache-Control: no-store`. Las rutas desconocidas devuelven `404 {"error":"Not found"}`; los errores inesperados devuelven `500` (`409` mientras hay una limpieza de chat en curso).

| Prefijo | Propósito |
| --- | --- |
| `/auth/*` | Better Auth detrás de una lista permitida: `sign-in/email`, `sign-up/email`, `sign-out`, `get-session` (límite de cuerpo de 16 KB) |
| `/me` | Perfil, `/model`, `/privacy`, `/photo`, `/debug-export`, `/mcp` (conexiones e inicio/renovación de OAuth) |
| `/onboarding` | Opciones, estado e inicio del círculo de onboarding |
| `/contacts` | CRUD de contactos, energía, iniciativa, voz, foto, archivar, vaciar, además de `/generation`, `/sharing` y, por contacto, `/personality`, `/mini-apps`, `/tasks`, `/links`, `/documents`, `/learning`, `/stickers`, `/native-actions`, `/native-remote`, `/schedules`, `/mcp` |
| `/contacts/:id/chat` | `GET/POST /turns`, `PUT /read`, `POST /activity`, reintento, adjuntos, `/transcriptions`, `/reactions`, `/media`, `/export` |
| `/groups` | Grupos, invitaciones, mensajes, confirmaciones, estado de lectura, agentes, respuestas, multimedia, tareas, documentos, aprendizaje, miniapps, reacciones, `/mcp` |
| `/home` | Feed Para ti, badge, visto, actualización, temas, comentarios de publicaciones |
| `/push` | `/device` (APNs), `/web-key`, `/web-device` (Web Push) |
| `/push-photos/:id` | Fotos firmadas con HMAC para notificaciones |
| `/native-execution` | Comprobantes de ejecución remota en el dispositivo |
| `/voices`, `/stickers`, `/link-previews` | Catálogo de voces, recorte y biblioteca de stickers, tarjetas de enlaces |
| `/mcp/oauth` | Metadatos del cliente, inicio y callback del OAuth de MCP |
| `/admin/*` | Solo a través de `AdminAPI` (o en local con `ADMIN_LOCAL_ROUTES=true`) |

## Autenticación

- **Better Auth** (`better-auth/minimal`) con `basePath: '/api/v1/auth'`, el adaptador de Drizzle sobre D1 (`provider: 'sqlite'`), email y contraseña (de 8 a 128 caracteres, todavía sin verificación de email).
- Las sesiones duran **7 días** (se renuevan a diario). El plugin `bearer({ requireSignature: true })` devuelve un token firmado en el encabezado `set-auth-token`.
- La API lee **solo** `Authorization: Bearer`; no tiene sesiones por cookie. Los proxies de web y de administración traducen sus cookies `httpOnly` a este encabezado.
- `BETTER_AUTH_SECRET` debe tener al menos 32 caracteres.
- El registro está controlado por el ajuste de administración `registration_enabled` (`403 REGISTRATION_CLOSED`).
- El rate limiter propio de Better Auth está desactivado en favor del limitador respaldado por D1 con clave en `CF-Connecting-IP`.

::note
La recuperación de contraseña y la verificación de propiedad del email no están configuradas; no hay servicio de email.
::

## Convenciones

- **Alcance por propietario.** Cada consulta filtra por el propietario de la sesión o por una membresía verificada.
- **Idempotencia.** Los IDs generados por el cliente (turnos, subidas, solicitudes de investigación) hacen que los reintentos sean seguros.
- **Publicación atómica.** Los cambios en varias filas usan `env.DB.batch()` con sentencias condicionales y revisiones (`history_revision`, revisiones de documentos) en lugar de bloqueos.
- **Trabajo acotado.** Las rondas de herramientas, la investigación, los turnos de trabajo, las programaciones y la energía tienen presupuestos explícitos ([límites agénticos](/es/features/agentic-work#presupuestos-y-límites)).
- **Validación.** Las entradas se validan a mano o con JSON Schema (`@cfworker/json-schema` para MCP); Zod se ejecuta en modo jitless para las librerías que lo necesitan.
- **Salida estrictamente pública.** `global_fetch_strictly_public` más una guarda de direcciones privadas por DNS-over-HTTPS para MCP.

## Agregar un endpoint

1. Agrega la ruta al módulo correspondiente en `src/` (o a un módulo nuevo montado en `src/app.ts`), usando el middleware de sesión bearer de ese módulo.
2. Si necesitas almacenamiento, agrega una migración nueva en `apps/api/migrations` (consulta [Migraciones de base de datos](/es/operations/database-migrations)).
3. Regenera los tipos si cambiaste `wrangler.jsonc`: `npm run types --workspace @wildcard/api`.
4. Ejecuta `npm run typecheck`.
5. Implementa el lado del cliente en **ambos**, iOS y web, y actualiza la guía afectada en `docs/` ([Contribuir](/es/operations/contributing)).
