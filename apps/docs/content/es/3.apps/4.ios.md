La aplicación nativa vive en `apps/ios` (`Wildcard.xcodeproj`). Está escrita en SwiftUI, apunta a **iOS 27.0** y **no usa paquetes Swift de terceros**.

## Targets

| Target | Sufijo del bundle ID | Rol |
| --- | --- | --- |
| `Wildcard` | `com.imlautaro.Wildcard` | La aplicación |
| `WildcardNotificationService` | `.NotificationService` | Notificaciones de comunicación con avatares de los contactos; ejecuta temporizadores y alarmas remotos |
| `WildcardWidgets` | `.Widgets` | Widget de contacto y una Live Activity de AlarmKit |
| `WildcardShare` | `.Share` | Hoja de compartir hacia un borrador de chat |
| `WildcardTests`, `WildcardUITests` | — | Pruebas unitarias y de UI |

`WildcardNativeShared` es una carpeta sincronizada que se compila dentro de la aplicación y de las tres extensiones (no es un framework). Las extensiones definen condiciones de compilación como `WILDCARD_NOTIFICATION_EXTENSION`.

Ajustes de Swift: modo de lenguaje Swift 5, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` y concurrencia accesible (approachable concurrency) en el target de la aplicación, y visibilidad de imports de miembros activada.

La estructura con sesión iniciada usa **un solo `NavigationStack` alrededor del `TabView`**; los editores se apilan sobre todo el diseño de pestañas y conservan la pestaña seleccionada.

## Red y sesión

- El origen de la API viene del ajuste de build `WILDCARD_API_URL` (clave de Info.plist `WildcardAPIURL`). La aplicación se comunica con la API **directamente**, no a través del proxy web.
- Las solicitudes van a `api/v1/<path>` con `Authorization: Bearer <token>` sobre una `URLSession` efímera sin cookies y sin caché.
- El token de `set-auth-token` se guarda en el Keychain (`<bundleID>.auth`, cuenta `session`, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`) y se restaura al iniciar. Una sesión expirada lo borra.

## Caché

La regla del proyecto es **usar caché por defecto** (`AGENTS.md`, `docs/caching.md`):

- `NavigationSnapshotCache<Value>`: una LRU en el main actor (8 entradas) para pantallas secundarias, que se reutiliza de forma síncrona al navegar y se revalida en segundo plano.
- `PrivateImageCache`: caché en memoria con alcance de cuenta más caché protegida en disco (`PrivateImages-v1`) para avatares, imágenes de chats, audio de voz e imágenes de vistas previas de enlaces. Las claves incluyen la cuenta, el contexto de acceso, la identidad del recurso y la versión.
- Los stores de conversaciones conservan los chats cargados; `ConversationSync` consulta el chat visible cada segundo; la estructura principal se actualiza cada 15 segundos.

## Notificaciones push

- `aps-environment` viene de `APNS_ENVIRONMENT` (`development` en Debug, `production` en Release) y se envía a la API para que elija el host de APNs de sandbox o de producción.
- El token del dispositivo se registra con `PUT /api/v1/push/device` y se elimina al cerrar sesión.
- La extensión de servicio de notificaciones construye notificaciones de comunicación (`INSendMessageIntent`) y descarga avatares solo desde `/api/v1/push-photos/` en el host configurado.
- Los conteos de no leídos persisten en el servidor y aparecen en las filas, en la pestaña Chats y en el badge del ícono de la aplicación.

## Integraciones con el sistema

- **App Intents y Atajos**: abrir un contacto, redactar un mensaje, atajos del botón de Acción (`Native/NativeIntents.swift`).
- **Widgets**: widget de contacto (`WildcardContacts`) y una Live Activity de AlarmKit.
- **Universal links**: `applinks:$(WILDCARD_LINK_HOST)` para enlaces de contacto autorizados; la aplicación web sirve `/.well-known/apple-app-site-association`.
- **Experimentos nativos**: temporizadores, alarmas, Calendario y Recordatorios solicitados por un contacto, con permisos y comprobantes por dispositivo.
- **App Group** (`WILDCARD_APP_GROUP`) compartido por la aplicación y sus extensiones.

## Localización

Inglés y español con String Catalogs (`Localizable.xcstrings` por target, `InfoPlist.xcstrings`, `AppShortcuts.xcstrings`), con el inglés como clave. No hay ajuste dentro de la aplicación: Cuenta → Idioma abre el ajuste de idioma por aplicación del sistema.

## Configuración para tu propia cuenta

1. Selecciona tu equipo de firma y reemplaza los bundle identifiers (los IDs de las extensiones deben extender el ID de la aplicación).
2. Define `WILDCARD_API_URL` en los targets de la aplicación y del servicio de notificaciones (Debug y Release).
3. Reemplaza `WILDCARD_APP_GROUP` y `WILDCARD_LINK_HOST`, y activa App Groups, Associated Domains, Push Notifications y Communication Notifications para los App IDs.
4. Crea una clave de APNs y configura los secretos de build `APNS_*` del proyecto de la API, con `APNS_TOPIC` igual al bundle ID de la aplicación.

::note
Los releases de la API no actualizan las aplicaciones instaladas. Compila y distribuye la aplicación iOS por separado.
::
