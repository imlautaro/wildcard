La aplicación web (`@wildcard/web`, Worker `wildcard-web`) es una **single-page app** de Nuxt 4 (`ssr: false`) compilada con el preset `cloudflare_module` de Nitro. Su único código de servidor es el proxy de la API y el archivo `apple-app-site-association`. Guía de funciones: `docs/web.md`.

## Aspectos destacados de la configuración

```ts [apps/web/nuxt.config.ts (excerpt)]
export default defineNuxtConfig({
  extends: ['../../packages/ui'],
  modules: ['@nuxtjs/i18n'],
  ssr: false,
  runtimeConfig: { apiOrigin: 'http://localhost:8787' }, // solo en desarrollo
  nitro: {
    preset: 'cloudflare_module',
    cloudflare: { deployConfig: true, nodeCompat: true, wrangler: { preview_urls: true } },
  },
  i18n: { strategy: 'no_prefix', defaultLocale: 'en', detectBrowserLanguage: false /* … */ },
});
```

`nitro.cloudflare.wrangler` sobrescribe `apps/web/wrangler.jsonc`; Nitro combina ambos en `.output/server/wrangler.json`, que es lo que despliega el release.

## Rutas

| Área | Páginas |
| --- | --- |
| Autenticación y onboarding | `/sign-in`, `/onboarding`, `/join`, `/invitations` |
| Chats | `/chats`, `/chats/[id]` |
| Contactos | `/contacts`, `/contacts/new`, `/contacts/[id]/{edit, personality, sharing, links, learning, tasks, connections}`, miniapps y documentos |
| Grupos | `/groups/new`, `/groups/[id]`, `/groups/[id]/{members, learning, tasks, connections}`, miniapps y documentos |
| Para ti | `/updates` |
| Cuenta | `/account`, `/account/connections`, `/mcp/oauth-complete` |
| Alternativa a lo nativo | `/native`, `/native/contact` (enlaces de contacto autorizados abiertos fuera de iOS) |

`app/middleware/auth.global.ts` restaura la sesión, envía a los usuarios sin sesión a `/sign-in` y las cuentas sin terminar a `/onboarding`.

## El proxy de la API

`server/api/v1/[...path].ts` es el único camino hacia la API. En producción llama al service binding `API`; en desarrollo llama a `runtimeConfig.apiOrigin`. Aplica listas permitidas de métodos, encabezados de solicitud y encabezados de respuesta, exige el mismo origen para las mutaciones, reenvía `CF-Connecting-IP` y convierte la cookie de sesión en un encabezado bearer. Consulta [Workers → Service bindings](/es/cloudflare/workers#service-bindings).

| Cookie | `__Host-wildcard_session` (`wildcard_session` en desarrollo) |
| --- | --- |
| Atributos | `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, 7 días |
| Se define | Al iniciar sesión o registrarse, a partir del encabezado `set-auth-token` de la API; se renueva con un `GET /api/v1/me` exitoso |
| Se borra | Al cerrar sesión o ante un `401` |

El navegador nunca ve el token, así que un XSS no puede exfiltrarlo y la API no necesita CORS.

## Capa de datos y caché

- `app/utils/api.ts` hace `fetch('/api/v1/…', { credentials: 'same-origin', cache: 'no-store' })` en el mismo origen. Un `401` expira la sesión; `0`, `502`, `503` y `504` se tratan como fallos transitorios que mantienen visible el contenido en caché.
- No hay Pinia. **37 composables** guardan el estado propio de la sesión en refs con alcance de módulo y registran un reinicio con `useSession`, de modo que cerrar sesión o cambiar de cuenta vacía todas las cachés.
- Las conversaciones mantienen hasta 20 chats en memoria; las imágenes usan una LRU de blob URLs de 150 entradas. Las reglas de caché de cada función están en `docs/caching.md`.

::warning
`useSession` no debe importar otros composables: un ciclo de imports hizo caer producción el 1 de noviembre de 2026. Registra los reinicios desde la dirección contraria.
::

La lista de chats muestra **Borrador:** para el texto sin enviar solo después de salir de su chat privado o grupo. Mientras esa conversación está abierta, su fila conserva la vista previa habitual de actividad, reacción o último mensaje. Al volver, el texto se restaura en el campo de escritura y se oculta la etiqueta de borrador; los borradores se mantienen solo en la memoria de la sesión.

## Polling

`usePolling` solo se ejecuta mientras la pestaña está visible y actualiza de inmediato cuando vuelve a estar visible.

| Qué | Intervalo |
| --- | --- |
| Chat o grupo abierto, lista de chats | 1 s |
| Invitaciones, badge de Para ti | 15 s |
| Círculo de onboarding | 3 s |
| Energía, teléfonos, información de mensajes, documentos, tableros de tareas | 5–20 s |
| Feed Para ti | 4 s mientras se cura, si no 60 s |
| Pestaña oculta (con Web Push activado) | Actualización de la lista cada 30 s |

## Web Push

`public/sw.js` solo gestiona push: no guarda nada en caché y nunca intercepta fetches. `useWebPush` lo registra, lee la clave VAPID desde `/api/v1/push/web-key`, guarda la suscripción con `PUT /api/v1/push/web-device` y muestra el conteo de no leídos en el título de la pestaña (`Wildcard (N)`). Las notificaciones se suprimen para un chat que está visible en una pestaña.

## Localización y apariencia

- Inglés y español con `@nuxtjs/i18n` (`no_prefix`), un archivo JSON por área en `i18n/locales/<en|es>/`. Cuenta → Idioma ofrece Sistema, English y Español (clave de `localStorage` `wildcard-language`).
- Tema Sistema, Claro u Oscuro desde la capa de UI (clave de `localStorage` `wildcard-theme`). El CSS oscuro debe apuntar a `:root[data-theme="dark"]`.

## Diferencias entre plataformas

La aplicación web iguala a iOS función por función, salvo donde los navegadores no pueden: no hay APNs (en su lugar, Web Push), no hay temporizadores, alarmas, Calendario ni Recordatorios nativos (en su lugar, una guía y una alternativa por enlace de contacto), y hay una exportación de depuración exclusiva de la web.
