Wildcard funciona por completo sobre Cloudflare: Workers, D1, R2 y Workflows. Tu instalación es la API y la app web en tu propia cuenta, con tu propia base de datos y tus propias claves. No editas nada del repositorio: la cuenta, los recursos y las URLs se resuelven al publicar, y el primer release crea la base de datos D1 y el bucket de R2 privado.

## Qué necesitas

- Una **cuenta de Cloudflare** con Workers, D1, R2 y Workflows disponibles en su plan, y un subdominio `workers.dev` (abrir **Workers & Pages** una vez en el dashboard lo crea).
- Una **cuenta de GitHub**.
- Una **clave de la Meta Model API** con acceso a Muse Spark 1.3 y Muse Voice Transcribe.
- Opcional: una clave de **ElevenLabs** para las voces de los contactos, una cuenta de **Apple Developer** para la app de iPhone y sus notificaciones (APNs, App Groups, Associated Domains) y claves **VAPID** para las notificaciones web (`node scripts/generate-vapid-keys.mjs`).

## Deploy to Cloudflare

La forma más rápida, y la que recomendamos:

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button){width="220" :zoom="false"}](https://deploy.workers.cloudflare.com/?url=https://github.com/imlautaro/wildcard)

::steps{level="3"}

### Haz clic en el botón

Copia el repositorio en tu cuenta de GitHub (un repositorio nuevo con un solo commit "source repo import", no un fork) y crea un proyecto de Workers Builds conectado al Worker `wildcard-api`. Su comando de deploy, `npm run deploy`, publica la API y luego compila y publica la app web, así que ambos Workers salen de ese único proyecto.

### Completa el formulario

- Mantén el nombre de Worker **`wildcard-api`**. El service binding de la app web apunta a él; un proyecto renombrado falla con un mensaje que lo indica.
- Ingresa `META_API_KEY`. El formulario pide cada clave del `.env.example` de la raíz; se guarda como secret del Worker `wildcard-api` y los releases la conservan.
- Mantén los comandos precargados: build `npm run build`, deploy `npm run deploy`.

### Espera el primer build

Tarda unos dos minutos porque aplica todas las migraciones. Tu app queda en `https://wildcard-web.<subdomain>.workers.dev`, donde `<subdomain>` es el subdominio `workers.dev` de tu cuenta. Las respuestas pueden tardar durante los primeros minutos; consulta [Solución de problemas](/es/operations/troubleshooting).

### Agrega las claves opcionales

Para las voces de los contactos, agrega `ELEVENLABS_API_KEY` como secret del Worker `wildcard-api` (**Settings → Variables and secrets**). A partir de ahí, cada push a `main` del repositorio nuevo publica ambos Workers.
::

## Otras formas de desplegar

¿Prefieres un fork con GitHub Actions, o un proyecto de Workers Builds por Worker? Elige **un solo** método por instalación: si usas dos para los mismos Workers, se publican dos veces.

::tabs
  :::tabs-item{label="GitHub Actions"}
  `.github/workflows/deploy.yml` se activa de forma explícita. En cada push a `main` (o en una ejecución manual) comprueba los tipos, publica la API y luego compila y publica la app web. No publica el panel de administración, el sitio ni las Docs, y no compila Previews de ramas.

  Haz un fork del repositorio y, en el fork, abre **Settings → Secrets and variables → Actions** y agrega:

  | Tipo | Nombre | Obligatorio |
  | --- | --- | --- |
  | Variable | `WILDCARD_DEPLOY` = `true` | Sí (activa el workflow) |
  | Secreto | `CLOUDFLARE_API_TOKEN` | Sí |
  | Secreto | `META_API_KEY` | Sí |
  | Secreto | `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*` | Opcionales (cada grupo, completo o vacío) |
  | Variable | `CLOUDFLARE_ACCOUNT_ID` | Cuando el token puede ver varias cuentas |
  | Variable | `WILDCARD_API_URL`, `WILDCARD_WEB_URL`, `WILDCARD_SUPER_ADMIN_USER_IDS` | Opcionales |

  Crea el token de API desde la plantilla **Edit Cloudflare Workers**, agrega **Account → D1 → Edit** y limítalo a tu cuenta (no hacen falta zonas). Nunca hagas commit de su valor.

  Habilita Actions en el fork y luego haz push a `main` o ejecuta manualmente el workflow **Deploy**. La primera ejecución crea D1, R2, ambos Workers, los Workflows y el trigger de Cron.
  :::

  :::tabs-item{label="Workers Builds"}
  Conecta a tu fork un proyecto de Workers Builds por Worker, rama `main`, raíz `/`:

  - **API** (`wildcard-api`): build `npm ci && npm run typecheck`, deploy `npm run release:ci`, previews desactivadas. Credencial: edición de Workers Scripts, edición de D1, edición de Workflows, edición de R2 y lectura de la cuenta. Agrega el secreto de build cifrado `META_API_KEY` (y los opcionales `ELEVENLABS_API_KEY`, `APNS_*`, `VAPID_*`). Agrega `CLOUDFLARE_ACCOUNT_ID`, `WILDCARD_API_URL`, `WILDCARD_WEB_URL` o `WILDCARD_SUPER_ADMIN_USER_IDS` como variables de build solo cuando los necesites.
  - **Web** (`wildcard-web`), una vez que exista la API: build `npm ci && npm run typecheck:web && npm run build:web`, deploy `npm run release:web`. Credencial: edición de Workers Scripts y lectura de la cuenta. Para las Previews por rama, habilita los builds que no son de producción con el comando de preview `npm run preview:web`.

  Copia las rutas de inclusión de `docs/workers-build-paths.json` en **Settings → Builds** de cada proyecto y elimina el `*` predeterminado (consulta los [watch paths](/es/cloudflare/workers-builds#watch-paths)). Haz push de un commit: el release de la API crea D1 y R2 si hace falta, migra D1, genera `BETTER_AUTH_SECRET`, sube los secretos y publica la API con sus Workflows y su Cron.
  :::
::

## Comprueba que funciona

Regístrate en tu app web y habla con un contacto. Para comprobarlo desde una terminal (Node.js 24+, en un clon del repositorio):

```bash [Terminal]
npm run smoke -- https://wildcard-web.<subdomain>.workers.dev
```

La prueba de humo registra una cuenta descartable, crea un contacto, envía un mensaje y espera la respuesta del modelo, lo que demuestra que el proxy web, la autenticación, D1, los Workflows y `META_API_KEY` funcionan juntos. La cuenta creada permanece; elimínala desde la configuración de Cuenta de la app. Consulta [Releases](/es/operations/releases#verificar-un-release) para las comprobaciones que no necesitan una cuenta.
