## Configuración

```jsonc [apps/api/wrangler.jsonc]
"r2_buckets": [
  { "binding": "CONTACT_PHOTOS", "bucket_name": "wildcard-contact-photos" }
]
```

A pesar del nombre de su binding, `CONTACT_PHOTOS` guarda **todos** los archivos multimedia privados. El bucket es privado: el acceso por `r2.dev` está desactivado y no hay dominios personalizados públicos. Los clientes nunca reciben URLs del bucket; cada objeto se transmite desde una ruta autorizada de la API que verifica la propiedad, la membresía y la versión actual.

## Estructura de claves de los objetos

| Clave | Contenido |
| --- | --- |
| `users/{owner}/{version}.jpg` | Foto de perfil de la cuenta |
| `contacts/{owner}/{contactID}/{version}.jpg` | Retrato del contacto (los contactos compartidos reutilizan el objeto del creador) |
| `groups/{groupID}/{version}.jpg` | Foto del grupo |
| `attachments/{user}/{contact}/{turn}/{uuid}` | Adjuntos de chats privados (imágenes y PDF, hasta 5 MiB) |
| `…/voice-a{attempt}-{i}` | Burbujas de respuesta habladas |
| `…/sticker-a{attempt}` | Stickers enviados |
| `…/image` | Imágenes reenviadas entre participantes de un contacto compartido |
| `group-attachments/{group}/{owner or agent}/…` | Archivos multimedia de grupos |
| `generated/{imageID}/{index}.jpg` | Imágenes generadas por contactos (álbumes de hasta tres) |
| `users/{id}/stickers/{id}.png` | Biblioteca de stickers de una persona |
| `contacts/{owner}/{agent}/stickers/{id}.png` | Biblioteca de stickers de un contacto |
| `link-previews/{hash}` | Imágenes en caché de vistas previas de enlaces |

Las claves de objetos que pertenecen a chats se registran en `chat_attachment_object` para poder eliminarlas junto con su chat.

## URLs firmadas para fotos de push

La extensión de servicio de notificaciones de iOS debe poder descargar los avatares de las notificaciones sin una sesión. La API emite URLs de corta duración bajo `/api/v1/push-photos/:id`, firmadas con un HMAC derivado de `BETTER_AUTH_SECRET`; la extensión descarga fotos solo desde esa ruta en el host de API configurado.

## Limpieza

- Reemplazar una foto escribe una nueva clave versionada y elimina la anterior en la medida de lo posible (best-effort).
- La eliminación de chats, contactos, grupos y cuentas encola borrados de R2 en el outbox `resource_cleanup` de D1, que el Cron de cada minuto reintenta.
- `cleanAttachments` elimina los objetos de adjuntos huérfanos.

## Aprovisionamiento

```bash [Terminal]
npm run infra:photos -- --create   # crea el bucket configurado una vez y luego lo verifica
npm run infra:photos               # verifica un bucket existente
```

El script nunca publica el Worker ni habilita el acceso público. La credencial de release necesita acceso al bucket además de sus permisos de Workers, D1 y Workflows. En local, `wrangler dev` emula el bucket en `apps/api/.wrangler/`; no agregues `remote: true`.
