Wildcard se ejecuta por completo en la plataforma para desarrolladores de Cloudflare. **No hay KV, ni Durable Objects, ni Queues, ni servicio de email, ni entorno de staging**.

## Mapa de servicios

| Servicio | Recurso en esta instalación | Usado por | Por qué |
| --- | --- | --- | --- |
| [Workers](/es/cloudflare/workers) | `wildcard-api`, `wildcard-web`, `wildcard-admin`, `wildcard-site`, `wildcard-docs` | Todos | Runtime serverless para la API, las dos aplicaciones Nuxt y los sitios estáticos |
| Assets estáticos | `ASSETS` (web, admin), Workers solo de assets (site, docs) | Web, admin, site, docs | Servir desde el edge los archivos front-end compilados |
| Service bindings | `API` → `wildcard-api`; `API` → `wildcard-api#AdminAPI` | Web, admin | Llamadas privadas de Worker a Worker sin un salto público ni CORS |
| Entrypoint con nombre | `AdminAPI` (`WorkerEntrypoint`) | API | Una superficie de administración que no es accesible desde el origen público de la API |
| [D1](/es/cloudflare/d1) | `wildcard-db` (binding `DB`) | API | Datos relacionales, sesiones, rate limits, búsqueda FTS5, outboxes |
| [R2](/es/cloudflare/r2) | `wildcard-contact-photos` (binding `CONTACT_PHOTOS`) | API | Objetos multimedia privados |
| [Workflows](/es/cloudflare/workflows-and-cron) | `wildcard-chat` (`ChatWorkflow`), `wildcard-onboarding` (`OnboardingWorkflow`) | API | Generación duradera en varios pasos que sobrevive a reinicios y a aplicaciones cerradas |
| [Cron Triggers](/es/cloudflare/workflows-and-cron#el-cron-de-cada-minuto) | `* * * * *` | API | Recuperación, despacho, reintentos de push y limpieza cada minuto |
| [Workers AI](/es/cloudflare/ai) | Binding `AI` | API | Embeddings `@cf/baai/bge-m3` para la memoria semántica opcional |
| [AI Gateway](/es/cloudflare/ai#ai-gateway) | Gateway `wildcard`, proveedor personalizado `meta` (opcional, actualmente desactivado) | API | Observabilidad del gasto y los metadatos de las llamadas a Meta |
| Workers Observability | Logs (muestreo 1) y trazas (muestreo 0.01 en la API) | API, web, admin | Depurar releases y fallos |
| [Workers Builds](/es/cloudflare/workers-builds) | Un proyecto por Worker sobre `imlautaro/wildcard`, rama `main` | Todos | Releases automáticos a partir de los commits enviados |
| URLs de preview | Branch Previews para `wildcard-web` | Web | Revisar una rama en `https://<branch>-wildcard-web.<subdomain>.workers.dev` |
| `workers.dev` | Todos los Workers | Todos | Orígenes públicos (no hay dominios personalizados configurados) |

## Obligatorio frente a opcional

::field-group
  :::field{name="Obligatorio" type="core"}
  Worker de la API, D1, R2, ambos Workflows, el Cron de cada minuto, el secreto de runtime `BETTER_AUTH_SECRET`, `META_API_KEY` para cualquier función de modelos y Workers Builds para los releases.
  :::

  :::field{name="Obligatorio para la aplicación web" type="web"}
  Worker web con su service binding `API` y su propio proyecto de Workers Builds.
  :::

  :::field{name="Opcional" type="extras"}
  Worker de administración, sitio de marketing, sitio de documentación, AI Gateway, memoria semántica (Workers AI), Previews web, dominios personalizados, Cloudflare Access delante del panel de administración.
  :::
::

## Planes y límites

- El hash de contraseñas de Better Auth consume tiempo de CPU. Revisa el límite de CPU de Workers de tu plan antes de abrir el registro al público.
- D1, R2, Workflows y Workers AI consumen las cuotas de la cuenta. Nada en el código cambia la configuración de facturación.
- Los Workflows conservan los resultados de sus pasos; la API guarda en D1 solo lo que necesita y limpia las instancias de Workflow mediante el outbox de limpieza cuando se eliminan chats.

## Valores específicos de la cuenta

Los archivos de Wrangler versionados no contienen `account_id`, ID de D1, URLs de la instalación ni IDs de administradores. El release de la API los resuelve para la cuenta de destino (consulta [Aprovisionamiento](/es/operations/provisioning#qué-resuelve-el-release)):

- Cuenta: `CLOUDFLARE_ACCOUNT_ID` o la única cuenta de la credencial.
- D1 y R2 por nombre (`WILDCARD_DB_NAME`, `WILDCARD_PHOTOS_BUCKET`), creados en el primer release.
- `BETTER_AUTH_URL` y `MCP_WEB_ORIGIN` desde `WILDCARD_API_URL` / `WILDCARD_WEB_URL`, o desde el subdominio `workers.dev` de la cuenta.
- `SUPER_ADMIN_USER_IDS` desde `WILDCARD_SUPER_ADMIN_USER_IDS`.

Todavía se editan a mano cuando hace falta: los `name` de los Workers y Workflows (solo si ya están en uso), el `WILDCARD_API_URL` de iOS y las URLs del sitio y de la documentación.
